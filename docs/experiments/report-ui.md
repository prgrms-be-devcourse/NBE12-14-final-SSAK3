# SCRUM-171 회고 보고서 화면

## 범위와 실행

React 화면과 가상 응답 미리보기를 구현한다. 운영 보고서 API, 로그인·강연방 소유권 검증 연동, DB 저장은 포함하지 않는다. 실제 생성·조회 API 연결은 백엔드 완성 후 진행한다. 보고서 수정·재생성·PDF 다운로드는 이번 범위에서 제외한다.

저장소의 `frontend` 디렉터리에서 `npm run dev` 실행 후 `/preview/reports`로 접속한다. 예: `http://localhost:5173/preview/reports`. 기존 `/`의 STT 확인 화면은 유지한다.

미리보기 상단에서 4가지 보고서 샘플과 강연 진행 중·기록 정리 중·생성 가능·생성 대기·처리 중·실패·빈 기록·STT만 있는 상태·조회 연결 오류·생성 응답 유실·권한 없음 상태를 선택한다. 생성 가능 상태의 버튼은 메모리 내 가상 상태만 변경한다. 생성 중 샘플은 조회가 진행되면 완료로 전환된다. 새로고침하면 샘플 선택과 상태는 초기화된다.

실제 서버 요청·LLM 호출·브라우저 저장소 쓰기는 없다. 모든 입력은 가상 데이터임을 상단에 표시한다. `sample-content.json`은 기존 실험의 가상 채팅과 생성 요약을 사용하고, 강사 발언은 `preview.js`의 별도 가상 문장으로 대체했다. 일반 사례의 청중 AI 요약 역시 표시 동작 확인용 가상 내용이다. 사용자 업로드 전사 원문과 작성자 정보는 프론트에 포함하지 않는다. 따라서 이 미리보기는 원래 LLM 실험의 정확도 재평가 자료가 아니다.

## 확정한 화면 동작

- 전체 요약의 주요 관심사·보충 설명 검토 지점·다음 강연 제안을 먼저 표시한다. 각각 빈 목록이어도 제목과 빈 상태 안내를 유지한다.
- 일반 항목은 바로 아래에서 근거를 펼친다. 상반 의견은 한 카드에 동일한 스타일로 모두 표시하고 입장별 근거를 따로 펼친다. 상위 합집합 근거는 중복 표시하지 않는다.
- 근거의 시간대 이동 버튼은 대상 구간을 펼치고 기록으로 스크롤·키보드 포커스를 옮긴 뒤 4초간 강조한다. 근거가 없으면 임의 연결하지 않고 확인 불가 안내를 표시한다.
- 타임라인은 강연 시작 후 경과 시간으로 표시한다. 상단 실제 날짜·시각은 한국 시간임을 명시한다. 날짜는 샘플의 가상 기준 시각이다.
- 각 시간대는 기본적으로 접는다. 같은 화면에서 여러 구간·근거를 펼칠 수 있으며 다른 구간으로 이동해도 열린 항목은 유지한다. 새로고침·재진입 시 펼침·강조 상태는 저장하지 않는다.
- 상세 기록은 강사 발언 / 청중 질문·의견 / 투표·이해도 체크 / 저장된 청중 AI 요약으로 구분한다. 실제 기록과 AI 생성 내용을 텍스트 및 색상으로 구분하며 새로운 분 단위 AI 해석은 만들지 않는다.
- 투표 근거는 최종 집계, 응답·미응답 인원, 시작·마감 시각을 표시한다. 개인별 투표 선택은 표시하지 않는다. 시작 구간에 표시된 결과가 해당 분 종료 시점의 상태를 뜻하지 않는다는 안내를 유지한다.
- 전체 데이터 한계는 상단에서 펼쳐본다. 관련 요약 항목·입장의 한계는 즉시 노출하고 시간대별 누락·분석 실패는 구간 내부 상단에 표시한다.
- 수집 기록 없음과 STT만 있는 보고서도 완료 결과로 표시한다. 남아 있는 발언은 조회할 수 있고 청중 반응을 추측하지 않는다.
- PC는 요약 3열, 850px 이하에서는 1열이다. 상반 의견은 항상 세로 배치한다.

## 생성 상태와 조회

| 화면 상태 | 동작 |
| --- | --- |
| 강연 진행 중 | 생성 비활성화 |
| 기록 정리 중 | 생성 비활성화, 상태 확인 |
| 생성 가능 | 보고서 생성 버튼 |
| PENDING / PROCESSING | 화면이 보일 때 5초 간격으로 조회, 중복 생성 차단 |
| COMPLETED | 저장된 결과 표시, 자동 조회 중단 |
| FAILED | 공통 실패 안내, 자동 조회 중단, 재생성 버튼 없음 |
| 조회 네트워크 오류 | 자동 조회 중단, 수동 상태 확인 |
| 생성 요청 응답 유실 | 성공·실패 단정 없이 상태 확인만 제공, 생성 재전송 없음 |
| 인증·권한 오류 | 보고서 내용을 숨기고 로그인·접근 권한 안내 |

조회는 한 요청이 끝난 후 다음 5초 타이머를 예약해 겹치지 않는다. 탭이 숨겨지거나 화면을 떠나면 타이머를 해제하며 이미 시작한 요청은 완료될 수 있다. 화면을 떠난 뒤 도착한 응답은 상태에 적용하지 않는다. 숨겼던 탭으로 돌아오면 생성 중일 때 즉시 한 번 조회한다. 연결 오류로 자동 조회가 중단된 경우는 사용자가 상태 확인을 눌러야 재개한다.

## 후속 API 연결 지점

- `ReportPage({ source, room })`: 화면과 상태 조회를 조합한다. 강연방/로그인 계정이 바뀌면 컴포넌트를 새 `key`로 마운트해 이전 기록·진행 요청을 격리해야 한다.
- `source.load()`: `{ status, content }`를 반환하는 조회 어댑터. 운영에서는 저장된 보고서 GET을 연결한다. 상태 조회는 생성을 유발하지 않아야 한다.
- `source.create()`: 동일 형태의 생성 결과를 반환하는 어댑터. 운영에서는 보고서 POST를 연결한다. 기존 실패 보고서 재생성은 제공하지 않는다.
- `LIVE`, `NOT_READY`, `NOT_CREATED`는 프론트 어댑터의 화면 상태이며 새로운 서버 보고서 enum이 아니다. 강연 상태·준비 여부와 보고서 없음 응답을 연결해 구성해야 한다. 준비 여부를 클라이언트가 임의로 판단하지 않는다.
- 백엔드 응답의 `data` 포장 해제, HTTP 오류 매핑, CSRF 처리, 강연방/계정 격리와 투표 레코드의 최종 필드 대응은 운영 연동 시 수행한다. 현재 미리보기는 인증 보안 검증을 대신하지 않는다.
- `ReportView({ content, room })`: 확정된 overview·timeline·한계를 표시한다. 여러 시간대에 걸치는 근거는 기록 ID와 시간대별 목적지를 함께 사용한다. 프론트는 요약이나 근거를 새로 생성하지 않는다.

## 검증

`frontend`에서 실행:

```sh
npm test
npm run build
npx playwright test
```

보고서 브라우저 테스트는 근거 이동·포커스·강조, 여러 구간 펼침 유지, 새로고침 초기화, 상반 의견 분리, 빈 결과·STT만 있는 결과·누락 안내, 5초 조회, 탭 비활성화/복귀, 생성 응답 유실·조회 오류·권한 오류, 모바일 가로 넘침을 확인한다. 기존 STT 테스트도 함께 실행한다.
