# SCRUM-171 회고 보고서 화면

## 범위와 실행

로그인한 강연자가 강연을 종료하면 `/host/rooms/{roomId}`에서 보고서 생성 상태를 확인할 수 있다. ‘회고 보고서 보기’를 누르면 `/host/rooms/{roomId}/report`에서 저장된 요약과 근거를 읽을 수 있다.

저장소의 `frontend` 디렉터리에서 `npm run dev` 실행 후 `/preview/reports`로 접속한다. 예: `http://localhost:5173/preview/reports`. STT 확인 화면은 `/dev/stt`로 이동했고, `/`은 정식 인증 진입 경로다.

미리보기 상단에서 4가지 보고서 샘플과 강연 진행 중·기록 정리 중·생성 가능·생성 대기·처리 중·실패·빈 기록·STT만 있는 상태·조회 연결 오류·생성 응답 유실·권한 없음 상태를 선택한다. 생성 가능 상태의 버튼은 메모리 내 가상 상태만 변경한다. 생성 중 샘플은 조회가 진행되면 완료로 전환된다. 새로고침하면 샘플 선택과 상태는 초기화된다.

미리보기는 메모리 안에서 동작하며 모든 입력이 가상 데이터임을 상단에 표시한다. `sample-content.json`은 기존 실험의 가상 채팅과 생성 요약을 사용하고, 강사 발언은 `preview.js`의 가상 문장을 사용한다. 일반 사례의 청중 AI 요약도 표시 동작을 확인하기 위한 예시다.

‘일반 반응’의 후속 답변 후보는 화면 검증용으로 직접 작성했다. 질문 원문에서 강조된 구절을 확인하고, 보충 설명 초안에서 참고한 강사 발언을 별도로 열 수 있다.

## 확정한 화면 동작

- 전체 요약의 주요 관심사·보충 설명 검토 지점·다음 강연 제안을 먼저 표시한다. 각각 빈 목록이어도 제목과 빈 상태 안내를 유지한다.
- 일반 항목은 바로 아래에서 근거를 펼친다. 상반 의견은 한 카드에 동일한 스타일로 모두 표시하고 입장별 근거를 따로 펼친다. 상위 합집합 근거는 중복 표시하지 않는다.
- 근거의 시간대 이동 버튼은 대상 구간을 펼치고 기록으로 스크롤·키보드 포커스를 옮긴 뒤 4초간 강조한다. 근거가 없으면 임의 연결하지 않고 확인 불가 안내를 표시한다.
- 타임라인은 강연 시작 후 경과 시간으로 표시한다. 상단 실제 날짜·시각은 한국 시간임을 명시한다. 날짜는 샘플의 가상 기준 시각이다.
- 각 시간대는 기본적으로 접는다. 같은 화면에서 여러 구간·근거를 펼칠 수 있으며 다른 구간으로 이동해도 열린 항목은 유지한다. 새로고침·재진입 시 펼침·강조 상태는 저장하지 않는다.
- 상세 기록은 강사 발언 / 청중 질문·의견 / 투표·이해도 체크 / 저장된 청중 AI 요약으로 구분한다. 실제 기록과 AI 생성 내용을 텍스트 및 색상으로 구분하며 새로운 분 단위 AI 해석은 만들지 않는다.
- 투표 근거는 최종 집계, 응답·미응답 인원, 시작·마감 시각을 표시한다. 개인별 투표 선택은 표시하지 않는다. 시작 구간에 표시된 결과가 해당 분 종료 시점의 상태를 뜻하지 않는다는 안내를 유지한다.
- 전체 데이터 한계는 상단에서 펼쳐본다. 관련 요약 항목·입장의 한계는 즉시 노출하고 시간대별 누락·분석 실패는 구간 내부 상단에 표시한다.
- ‘기록 누락·분석 실패’ 샘플에서 전체 데이터 한계를 펼치면 강연 시간에 연결할 수 없는 발언 수와 원문을 확인할 위치를 볼 수 있다. 마지막 구간을 펼치면 복구 시각이 확인되지 않은 누락도 볼 수 있다.
- 수집 기록 없음과 STT만 있는 보고서도 완료 결과로 표시한다. 남아 있는 발언은 조회할 수 있고 청중 반응을 추측하지 않는다.
- PC는 요약 3열, 850px 이하에서는 1열이다. 상반 의견은 항상 세로 배치한다.
- 전체 요약과 시간대별 기록 사이의 ‘후속 답변 후보’에서 강사가 이어서 답하고 싶은 질문을 확인한다. 처음 3묶음을 표시하고 ‘더 보기’로 나머지를 펼친다. 질문 근거에서는 작성 시각과 전체 채팅 중 해당 질문 구절을 보고, 보충 설명 초안에서는 참고한 강사 발언을 별도로 펼칠 수 있다.

## 미리보기의 생성 상태와 조회

| 화면 상태 | 동작 |
| --- | --- |
| 강연 진행 중 | 생성 비활성화 |
| 기록 정리 중 | 생성 비활성화, 상태 확인 |
| 생성 가능 | 보고서 생성 버튼 |
| PENDING / PROCESSING | 화면이 보일 때 5초 간격으로 조회, 중복 생성 차단 |
| COMPLETED | 저장된 결과 표시, 자동 조회 중단 |
| FAILED | 공통 실패 안내, 자동 조회 중단, 재생성 버튼 없음 |
| 조회 네트워크 오류 | 자동 조회 중단, 수동 상태 확인 |
| 생성 요청 응답 유실 | 성공·실패 단정 없이 상태 확인만 제공, 생성 재전송 없음 |
| 인증·권한 오류 | 보고서 내용을 숨기고 로그인·접근 권한 안내 |

조회는 한 요청이 끝난 후 다음 5초 타이머를 예약해 겹치지 않는다. 탭이 숨겨지거나 화면을 떠나면 타이머를 해제하며 이미 시작한 요청은 완료될 수 있다. 화면을 떠난 뒤 도착한 응답은 상태에 적용하지 않는다. 숨겼던 탭으로 돌아오면 생성 중일 때 즉시 한 번 조회한다. 연결 오류로 자동 조회가 중단된 경우는 사용자가 상태 확인을 눌러야 재개한다.

## 실제 강연방에서 보고서 열기

- PC와 모바일 모두 종료 안내 아래, AI 요약·채팅 위에서 상태를 확인한다. `GET /api/v1/rooms/{roomId}/reports/status`를 대기·생성 중에 5초마다 조회하고 각 단계가 2분 이상 지속되면 지연을 안내한다. 일시적인 공급자 장애로 재시도 기회가 있는 경우 ‘보고서 생성 다시 시도’를 제공한다. 완료되면 ‘회고 보고서 보기’ 링크를 제공한다.
- 종료 시각에서 2초가 지난 뒤에도 서버가 `REPORT_NOT_FOUND`를 반환하면 ‘보고서 만들기’를 표시한다. 강연자가 누르면 같은 방의 `POST /reports`로 접수한다. 응답이 끊기면 ‘다시 불러오기’로 먼저 상태를 조회한다.
- 보고서 주소를 열면 방의 제목·강연 시각과 `GET /api/v1/rooms/{roomId}/reports`의 저장된 결과를 읽는다. 대기·생성 중·실패·미접수이면 해당 강연방으로 돌아간다. 본문 요청이 끊기면 페이지에서 ‘다시 불러오기’로 본문만 재조회한다. 상단의 ‘강연방으로 돌아가기’는 직접 접속해도 같은 방으로 연결된다.

## 자동 접수 시간 측정

로컬 Spring과 MySQL 8.4에서 각 방의 종료 트랜잭션 커밋 직후부터 자동 접수 트랜잭션 커밋 직후까지 같은 JVM의 단조 시계로 측정했다. 85건 모두 별도의 DB 조회로 접수를 확인했다.

| 조건 | 건수 | 중앙값 | 95백분위 | 최대 |
| --- | ---: | ---: | ---: | ---: |
| 서버 기동 후 첫 종료 | 1 | — | — | 45.326ms |
| 한 방씩 순차 종료 | 60 | 10.599ms | 17.584ms | 24.324ms |
| 6개 방 동시 종료, 4회 | 24 | 19.645ms | 35.199ms | 35.715ms |

서버가 `endedAt`의 초 미만을 버리므로 저장값이 실제 종료 시점보다 최대 약 1초 빠를 수 있다. 이 차이와 실측 최대 지연에 여유를 더해 수동 접수 기준을 `endedAt + 2초`로 정했다. 브라우저는 서버의 404 응답 시각으로 남은 대기를 계산한다. 측정 범위는 최초 접수까지이며, 마지막 청중 분석과 본문 생성에는 별도의 시간이 걸린다.

## 검증

`frontend`에서 실행:

```sh
npm test
npm run build
npx playwright test
```

보고서 브라우저 테스트는 근거 이동·포커스·강조, 여러 구간 펼침 유지, 새로고침 초기화, 상반 의견 분리, 빈 결과·STT만 있는 결과·누락 안내, 5초 조회, 탭 비활성화/복귀, 생성 응답 유실·조회 오류·권한 오류, 모바일 가로 넘침을 확인한다. 기존 STT 테스트도 함께 실행한다.
