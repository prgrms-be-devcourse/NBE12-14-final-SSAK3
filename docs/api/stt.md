# STT — 강연자 발언 기록

## 프론트엔드 전송 복구 정책 (SCRUM-170)

- SCRUM-170의 음성 인식은 기존 기획대로 브라우저 Web Speech API의 `SpeechRecognition`을 사용한다. 별도 STT 서비스의 직접 연동은 이번 구현 범위에 포함하지 않는다. 실제 브라우저에서 인식 품질과 장시간 동작을 검증한다.
- 음성 인식 언어는 한국어(`ko-KR`)로 고정한다. 이번 구현에는 언어 선택 UI를 포함하지 않으며, 영어 기술 용어의 인식 품질은 모의 강연에서 확인한다.
- 녹음을 시작하거나 재개할 때 세션 시작 응답의 `serverTime`을 기준으로 잡는다. 브라우저는 응답 수신 시점부터 각 음성 인식 이벤트까지 `performance.now()`로 잰 경과 시간을 더해 발언의 추정 시각(`segmentStartAt`, `segmentEndAt`)과 누락 구간의 시작·복구 시각(`startedAt`, `endedAt`)을 계산한다. 기존 세션에 복귀할 때도 그때 받은 `serverTime`을 사용한다. 응답 전송에 걸린 시간과 음성 인식 지연만큼 실제 사건 시각과 차이가 날 수 있다.
- 확정된 발언을 재전송할 때는 처음 계산해 보관한 시작·종료 시각을 그대로 보낸다. `receivedAt`은 서버의 최초 수신 시각으로 별도 저장한다. 화면과 보고서에는 발언 시각이 추정값임을 안내하고 모의 강연에서 오차를 확인한다.
- 추정 시작 시각은 해당 전사 결과를 처음 관측한 시각, 종료 시각은 해당 결과가 확정된 시각이다. 임시 결과 없이 바로 확정되면 시작·종료에 같은 시각을 사용한다. 결과 인덱스는 한 번의 인식 실행 안에서만 추적하고, 인식 재시작 시 추적 상태를 초기화한다. 확정된 결과가 다음 이벤트에 다시 포함되어도 중복 저장하지 않는다.
- 향후 실제 사용 브라우저가 발언 시작·종료 시각을 제공하는 것이 검증되면 새 발언의 시각 산정 방식을 변경할 수 있다. 기존 저장 기록과 전송 대기·재전송 중인 기록의 시각은 변경하지 않는다.
- 이번 구현에서는 시간 출처 컬럼을 추가하지 않고 기존 DB 구조와 API 시간 필드를 유지한다. 화면과 보고서에서 추정 시각임을 안내하며, 향후 API 제공 시각을 도입할 때 시간 출처 구분을 함께 설계한다.
- 녹음 시작 시 서버의 STT 세션 시작 응답과 `canRecord=true`를 확인한 뒤 음성 인식을 시작한다. 서버 연결 실패나 응답 유실로 시작 가능 여부를 확인하지 못하면 음성 인식을 시작하지 않는다. 시작 요청을 재시도할 때는 최초의 `startKey`를 유지하여 기존 세션을 확인한다.
- 서버 세션 생성 후 최초 마이크·음성 인식 시작에 실패하면 해당 세션의 종료 API를 `reason=ERROR`로 호출하고 실패 사유와 권한 설정 등 필요한 안내를 표시한다. 최초 인식 시작 실패에는 자동 재시작하지 않는다. 정상 인식 시작 이후의 일시 중단에는 기존 복구 정책을 적용한다.
- 최초 시작 실패 후 강연자가 다시 시작하면 새 `startKey`로 새 세션을 생성한다. 기존 세션 종료 응답이 유실되거나 종료 요청이 실패하면 종료 완료로 표시하지 않고 기존 세션의 종료 처리를 재시도한다. 기존 세션 종료가 확인되기 전에는 새 세션의 녹음을 시작하지 않는다.
- 임시 전사는 화면에 '인식 중'으로 구분하여 표시하고, 결과가 확정되면 확정 전사 목록으로 옮긴다. 임시 결과는 변경되거나 사라질 수 있으며 서버 저장과 미전송 기록 복구 대상에는 확정 전사만 포함한다.
- 서버 저장이 확인되지 않은 확정 전사는 브라우저 저장소에 보관하여 새로고침 후에도 복구한다.
- 재전송에 필요한 강연방·세션 식별자, `startKey`, `segmentKey`, 전사 텍스트와 발언 추정 시작·종료 시각을 함께 보관한다. 재전송 시 기존 키와 내용을 유지한다.
- `segmentKey`는 확정 전사 한 건마다 프론트에서 UUID를 한 번 생성한다. 같은 문장을 다시 말한 별개의 발언에는 새 UUID를 부여한다. 재전송하거나 새로고침 후 복구할 때는 보관한 UUID를 그대로 사용한다. 향후 생성 방식을 바꾸더라도 기존 저장 기록과 전송 대기 기록의 키는 변경하지 않는다.
- 서버 저장 성공(신규 저장 또는 동일 요청 재전송 성공)이 확인된 기록은 로컬 보관 대상에서 제거한다.
- 로컬 기록 복구가 서버 저장을 보장하지는 않는다. 종료된 세션의 신규 전사 저장 제한 등 기존 API 규칙을 유지한다.
- 강연자가 녹음 종료를 요청하면 음성 인식을 멈추고 마지막 확정 결과까지 보관한 뒤, '남은 기록 저장 중'을 표시하며 미전송 발언을 먼저 전송한다. 모두 저장되면 STT 세션 종료 API를 호출한다.
- 남은 기록 저장에 실패하면 '저장 재시도'와 '남은 기록을 서버에 저장하지 않고 종료'를 제공한다. 저장하지 않고 종료할 때 서버 저장이 확인되지 않은 발언 개수를 안내한다. 응답 유실로 이미 서버에 저장된 발언이 포함될 수 있으므로 해당 개수를 확정적인 유실 개수로 표현하지 않는다.
- '남은 기록을 서버에 저장하지 않고 종료'를 선택해도 남은 기록을 즉시 삭제하지 않는다. 해당 기록은 자동 재전송 대상에서 제외하고, 해당 계정에서 파일로 내려받거나 직접 삭제할 수 있게 한다. 서버 보고서에 반영되지 않을 수 있음을 안내한다.
- 미저장 기록을 포기해도 서버 세션 종료 성공 응답을 받기 전에는 종료 완료로 표시하지 않는다.
- 녹음 의도가 유지된 상태에서 음성 인식이 예상치 못하게 중단되면 '음성 인식 중단' 상태를 표시하고 누락 구간을 연다. 서버 전송 실패만으로 음성 인식 누락 구간을 만들지는 않는다.
- 예상치 못한 인식 중단에는 자동 재시작을 한 번 시도한다. 실패하면 자동으로 반복 시도하지 않고 '다시 시작' 버튼을 제공한다. 실제 음성 인식이 다시 시작되면 열린 누락 구간을 닫는다.
- 자동 재시작 직후 다시 중단되는 반복을 막기 위해, 재시작 후 30초 동안 정상 인식 상태를 유지한 경우에만 다음 중단에 대한 자동 재시작 기회를 갱신한다. 강연자가 직접 재개하는 경우에는 새 시도로 취급한다.
- 마이크 권한 거부에는 자동 재시도를 하지 않고 권한 설정 안내를 제공한다. 강연자가 직접 녹음을 종료한 경우에도 자동 재시작하지 않는다.
- 새로고침 후에는 기존 세션 정보와 미전송 확정 전사를 복구한다. 로그인·강연방 소유권과 세션 상태를 확인한 뒤 저장 가능한 기록을 재전송한다.
- 새로고침 후 마이크는 자동으로 켜지 않는다. '음성 인식이 중단되어 있습니다'와 '녹음 재개' 버튼을 표시하고, 강연자가 재개를 선택하면 기존 세션에서 음성 인식을 다시 시작한다. 강연방이나 세션이 이미 종료되었다면 재개를 차단하고 사유를 안내한다.
- 탭의 갑작스러운 종료 등으로 복구할 때 중단 시각이 보관되어 있으면 그 시각을 사용한다. 중단 시각을 확인할 수 없으면 마지막 발언 시각 등으로 과거 누락 구간을 임의 생성하지 않고 '이전 녹음의 정확한 중단 시각을 확인할 수 없습니다'를 안내한다.
- 중단 시각이 없는 경우에는 복구 화면에서 인식이 꺼져 있음을 확인한 시점부터 실제 재개 시점까지를 누락 구간으로 기록한다. 기존에 열린 누락 구간이 있으면 이를 유지하여 중복 생성하지 않으며, 새 누락 구간 생성은 기존 API의 강연방·세션 상태 조건을 따른다. 확인되지 않은 과거 구간을 정상 기록 구간으로 단정하지 않는다.
- 서버에 전달하지 못한 누락 구간 시작·종료 요청도 브라우저 저장소에 보관하여 새로고침 후 복구한다. 재전송에 필요한 식별자와 최초 키·시각·사유를 유지한다.
- 연결 복구 후 누락 구간 요청은 발생 순서대로 전송한다. 시작 요청의 성공 응답으로 `gapId`를 확보한 뒤 해당 종료 요청을 보낸다. 다음 누락 구간이 있다면 앞선 구간 종료를 처리한 후 시작 요청을 보낸다.
- 녹음 종료 전 저장 대상에는 미전송 확정 전사뿐 아니라 누락 구간 시작·종료 요청도 포함한다. 각 요청은 서버 처리 성공이 확인된 뒤 로컬 전송 대기 대상에서 제거하며, 기존 API의 상태·시각 검증 규칙을 유지한다.
- 같은 브라우저의 탭 간 조정이 가능한 범위에서는 같은 강연방의 녹음을 한 탭만 담당한다. 먼저 녹음을 시작한 탭이 담당하며, 다른 탭에는 '다른 탭에서 녹음 중입니다'를 표시하고 녹음 시작을 막는다.
- 담당 탭이 닫힌 후에는 다른 탭에서 강연자가 '녹음 재개'를 눌러 이어간다. 기존 탭의 녹음 담당 여부를 확인하지 못한 상태에서는 마이크를 켜지 않는다. 시크릿 창·별도 브라우저·다른 기기는 이 탭 간 조정의 보장 범위에 포함하지 않는다.
- 브라우저 저장소에 기록을 보관할 수 없으면 음성 인식을 멈추고 '브라우저에 기록을 보관할 수 없어 녹음을 중단했습니다'를 표시한다. 이미 확보한 기록은 가능한 만큼 서버에 전송한다.
- 로컬 저장 실패로 중단한 경우에는 자동으로 인식을 재시작하지 않는다. 저장 기능이 정상으로 돌아온 것을 확인한 뒤 강연자가 '녹음 재개'를 눌러 재개한다. 저장 실패 중 메모리에만 남은 기록은 새로고침 후 복구를 보장하지 않는다.
- 녹음 중 API가 `401`을 반환하면 음성 인식을 멈추고 '로그인이 만료되어 녹음을 중단했습니다'를 표시한다. 미전송 확정 전사와 누락 구간 요청은 브라우저에 보관하고, 인증이 복구되기 전에는 전송 재시도를 중단한다.
- 같은 계정으로 다시 로그인하면 강연방 소유권과 세션 상태를 확인한 뒤 저장 가능한 기록의 전송을 재시도한다. 음성 인식은 자동으로 켜지 않고 강연자가 '녹음 재개'를 눌러 재개한다.
- 실행 중에는 15초 간격으로 로그인 사용자와 동일 `startKey`의 세션 상태를 확인한다. 강연 종료로 `canRecord=false`가 확인되면 인식을 중단하며, 각 저장 API도 서버의 현재 상태 검증을 따른다.
- 로컬 미전송 기록은 계정별로 구분한다. 다른 계정으로 로그인한 경우 이전 계정의 미전송 기록을 화면에 보여주거나 서버에 전송하지 않는다.
- 강연·세션 종료 등으로 서버가 미전송 기록의 저장을 최종적으로 거절하면 해당 기록의 자동 재전송을 중단하고 사유를 안내한다. 일시적인 연결 실패나 재로그인이 필요한 `401`과 구분한다.
- 최종적으로 저장이 거절된 기록은 즉시 삭제하지 않는다. 해당 계정에서 파일로 내려받거나 명시적으로 삭제할 수 있게 한다. 내려받은 기록은 서버 보고서에 자동으로 반영되지 않음을 안내한다.
- 일시적인 전송 실패에는 최초 실패 후 각 재시도까지 1초, 2초, 4초, 8초, 16초를 기다려 자동으로 최대 5회 재시도한다. 계속 실패하면 자동 재시도를 멈추고 '미전송 기록이 남아 있습니다'와 '저장 재시도' 버튼을 표시한다.
- 전송 재시도를 기다리거나 수동 재시도 상태여도 음성 인식과 브라우저 저장이 정상이면 확정 전사를 계속 보관한다. 새 기록이 추가되었다는 이유로 소진된 자동 재시도 횟수를 초기화하지 않는다. 로그인 만료와 최종 저장 거절에는 각각의 별도 처리 정책을 적용한다.
- 강사 화면은 음성 인식 상태와 기록 저장 상태를 별도로 표시한다. 음성 인식은 '인식 중', '인식 중단', '인식 종료' 등을, 저장 상태는 '서버 저장 완료', '미전송 발언 N건 · 재시도 중', '남은 기록 저장 중' 등을 구분하여 안내한다.
- '서버 저장 완료'는 그때까지 확정된 전사의 서버 저장이 확인되었다는 뜻이며, 아직 확정되지 않은 발언까지 저장되었다는 의미로 사용하지 않는다. 누락 구간 요청이 미전송 상태라면 이 역시 별도로 안내하여 전체 기록 저장이 완료된 것으로 오인하지 않게 한다.

모든 STT API는 로그인한 사용자의 `ROLE_HOST`와 강연방 소유권을 검증한다. 미인증 요청은 `401 UNAUTHENTICATED`, 강사 역할이 없거나 다른 강연자의 방에 접근하면 `403 FORBIDDEN`을 반환한다. 로그인 API가 발급한 서버 세션으로 인증하며, 로그아웃으로 무효화된 세션은 사용할 수 없다.


### [STT-01] STT 세션 시작

세션의 시작·종료 시각은 기존 배포 기준과 동일하게 DB의 `DATETIME`에 고정 오프셋 `+09:00`으로 기록한다. API는 이를 UTC로 반환하며, 진행 중인 세션의 `endedAt`은 `null`이다.

**POST** `/api/v1/rooms/{roomId}/stt/sessions` — HOST, 강연방 소유자 — Request `{ "startKey": "9fad8ee6-dd0b-4402-9817-8da1b7144fe5" }`

```json
{ "data": { "sttSessionId": 701, "roomId": 10, "status": "RECORDING", "startedAt": "2026-11-17T01:00:02Z", "endedAt": null, "canRecord": true, "serverTime": "2026-11-17T01:00:02.345Z" } }
```

규칙: LIVE 여야 함, 마이크 권한 확인은 프론트에서 수행, 브라우저 Web Speech API 로 STT 시작, 강연방당 동시에 하나의 RECORDING 세션만 허용, 중지 후 재시작하면 새 세션 생성 가능. 엔터티: `stt_sessions`

시작할 때 새 UUID를 만들고 재시도에는 같은 키를 사용한다. 최초 생성은 `201`, 재시도는 기존 세션의 현재 상태와 `200`을 반환한다. 다른 키로 요청했을 때 이미 기록 중이면 `200`, `canRecord: false`를 반환한다. 마이크는 `canRecord: true`일 때만 켠다. 종료된 세션의 시작 키를 재전송해도 재시작하지 않는다.

`startedAt`은 세션의 최초 시작 시각이다. `serverTime`은 해당 요청에 응답할 때의 서버 시각(UTC, 밀리초 정밀도)이며, 같은 키로 다시 요청해도 새로 측정한다.

`canRecord`는 요청의 시작 키가 일치하고, 세션이 `RECORDING`이며, 강연방이 `LIVE`일 때만 `true`다. 강연방이 먼저 `ENDED`가 되면 세션이 아직 `RECORDING`이어도 같은 시작 키의 재전송에 `200 OK`와 `canRecord: false`를 반환한다.

### [STT-02, 03] STT 확정 발언 저장

**POST** `/api/v1/rooms/{roomId}/stt/sessions/{sessionId}/segments` — HOST, 강연방 소유자

Request

```json
{
  "startKey": "9fad8ee6-dd0b-4402-9817-8da1b7144fe5",
  "segmentKey": "browser-701-0001",
  "transcript": "Redis는 메모리 기반 데이터 저장소입니다.",
  "segmentStartAt": "2026-11-17T01:00:12Z",
  "segmentEndAt": "2026-11-17T01:00:19Z"
}
```

Response — 201 Created

```json
{
  "data": {
    "segmentId": 9001,
    "sttSessionId": 701,
    "segmentKey": "browser-701-0001",
    "transcript": "Redis는 메모리 기반 데이터 저장소입니다.",
    "segmentStartAt": "2026-11-17T01:00:12Z",
    "segmentEndAt": "2026-11-17T01:00:19Z",
    "receivedAt": "2026-11-17T01:00:20Z"
  }
}
```

강연방 소유권과 세션의 소속을 확인한 뒤, 요청의 `startKey`가 해당 세션을 시작한 키와 일치하는지 검증한다. 발언은 브라우저에서 확정된 전사만 전송한다. 공백뿐인 전사는 거부하고 발언 시작 시각은 종료 시각과 같거나 빨라야 한다.

- 새 `segmentKey`는 강연이 `LIVE`이고 세션이 `RECORDING`일 때 저장하고 `201`을 반환한다. 종료 후 신규 저장은 `409`로 거부한다.
- 같은 세션의 같은 `segmentKey`로 전사 텍스트와 발언 시작·종료 시각이 같은 요청이 오면, 종료 후에도 최초 저장 결과를 `200`으로 반환한다. 서버 수신 시각 `receivedAt`은 비교에서 제외하고 최초 값을 유지한다.
- 같은 키의 전사 내용이나 발언 시각이 다르면 `409`를 반환하고 기존 기록을 유지한다.
- 발언 시작·종료 시각은 밀리초 정밀도로 저장하고 비교한다. UTC 오프셋이 달라도 같은 순간이면 동일한 시각이다.
- 전사 구간의 발언 시작·종료 및 서버 수신 시각은 DB의 `DATETIME`에 고정 오프셋 `+09:00` 기준으로 기록한다. 조회 시 같은 오프셋으로 해석해 API에는 UTC 시각으로 반환한다.
- 진행 중인 강연과 세션에서는 앞선 발언이 늦게 도착해도 저장한다. 회고 타임라인은 `segmentStartAt`을 기준으로 구성하고 `receivedAt`에는 서버의 최초 수신 시각을 남긴다.
제약: `UNIQUE(stt_session_id, segment_key)` · 엔터티: `stt_segments`

### [STT-04] STT 누락 구간 시작 기록

**POST** `/api/v1/rooms/{roomId}/stt/sessions/{sessionId}/gaps` — HOST, 강연방 소유자

Request

```json
{ "startKey": "9fad8ee6-dd0b-4402-9817-8da1b7144fe5", "eventKey": "stt-701-gap-0001", "reason": "ERROR", "startedAt": "2026-11-17T01:25:00Z" }
```

Response — 201 Created

```json
{ "data": { "gapId": 8001, "sttSessionId": 701, "eventKey": "stt-701-gap-0001", "reason": "ERROR", "startedAt": "2026-11-17T01:25:00Z", "endedAt": null } }
```

브라우저가 음성 인식 중단을 알리면 `stt_gaps`에 누락 구간을 기록한다. 전사가 없는 시간만으로 오류를 판단하지 않는다.

브라우저는 중단과 복구를 관측할 때 각각의 시각을 서버 시계 기준으로 계산해 요청에 보관한다. 연결이 끊겨 나중에 전송하거나 새로고침 후 재시도해도 보관한 시각을 그대로 보낸다. 서버는 기존 규칙대로 초 단위로 저장한다.

- 같은 세션에서 같은 `eventKey`, `reason`, `startedAt`으로 재전송하면 기존 구간과 `200 OK`를 반환한다. 같은 키로 사유나 시작 시각을 다르게 보내면 `409 Conflict`를 반환한다.
- 세션당 열린 누락 구간은 하나다. 열린 구간이 있는 동안 새 `eventKey`로 시작을 요청하면 `409 Conflict`를 반환하고 처음 열린 구간의 시작 시각과 사유를 유지한다.
- 같은 세션에서 새 누락 구간의 `startedAt`이 직전에 닫힌 구간의 `endedAt`보다 이르면 `409 Conflict`를 반환한다. 두 시각은 초 단위로 비교하며, 같은 초에 이전 구간이 끝나고 새 구간이 시작되는 것은 허용한다.
- 새 누락 구간의 시작 시각이 음성 인식 세션의 시작 시각보다 이르면 `400 Bad Request`를 반환한다. 초 단위로 비교하며, 세션이 시작된 초에도 누락 구간을 열 수 있다.
- 새 `eventKey`로 누락 구간을 만들려면 강연방이 `LIVE`이고 세션이 `RECORDING`이어야 한다. 두 조건 중 하나라도 충족하지 않으면 `409 Conflict`를 반환한다.
- 권한과 `startKey` 검증 후 기존 이벤트를 먼저 확인한다. 강연방이나 세션이 종료된 뒤에도 같은 내용의 재전송이면 기존 구간의 현재 상태와 `200 OK`를 반환한다.

누락 구간 시작과 종료 모두 요청 본문에 해당 세션을 시작할 때 사용한 `startKey`(UUID)가 필수다. 서버는 강연방 소유권과 세션의 소속을 확인하고, 요청의 키가 세션의 시작 키와 다르면 `403 Forbidden`을 반환한다. 재전송에도 같은 검증을 적용한다.

새로 기록할 `startedAt` 또는 `endedAt`은 서버가 해당 요청을 받은 시각과 초 단위로 비교한다. 수신 시각보다 이후의 초이면 `400 Bad Request`를 반환하고, 같은 초이면 허용한다.

### [STT-04] STT 누락 구간 종료

**PATCH** `/api/v1/rooms/{roomId}/stt/sessions/{sessionId}/gaps/{gapId}/close` — HOST, 강연방 소유자

Request `{ "startKey": "9fad8ee6-dd0b-4402-9817-8da1b7144fe5", "endedAt": "2026-11-17T01:25:15Z" }`

```json
{ "data": { "gapId": 8001, "startedAt": "2026-11-17T01:25:00Z", "endedAt": "2026-11-17T01:25:15Z", "reason": "ERROR" } }
```

STT가 정상 재시작되면 누락 구간을 닫는다. 종료 시각은 시작 시각보다 빠를 수 없다. `startedAt`과 `endedAt`은 초 미만을 버려 기존 `DATETIME`에 저장한다. 시작·종료 요청을 재전송할 때도 같은 기준으로 비교하므로 같은 초에 속하는 값은 같은 시각으로 본다. 같은 초에 시작하고 끝난 누락 구간도 기록한다.

강연방이 먼저 `ENDED`가 되었더라도 세션이 `RECORDING`이고 누락 구간이 열려 있으면 지연 도착한 복구 요청을 처리한다. 요청의 `endedAt`이 강연 종료 시각과 같은 초이거나 더 이르면 해당 복구 시각으로 구간을 닫는다. 강연 종료 시각보다 늦으면 `400 Bad Request`를 반환하고 구간을 열린 상태로 유지한다.

음성 인식이 복구되기 전에 세션이 종료되면 서버가 열린 전사 누락 구간의 `endedAt`을 세션의 종료 시각으로 기록한다. 이때 구간을 열 때 기록한 `reason`을 유지한다.

정상 녹음 중 강연자가 직접 종료하면 클라이언트는 세션 종료 API만 호출한다. 서버는 새 누락 구간을 만들지 않는다.

이미 닫힌 구간에 종료 요청이 다시 들어오면 요청의 `endedAt`과 저장된 종료 시각을 비교한다. 같은 시각이면 기존 결과와 `200 OK`를 반환하고, 다른 시각이면 `409 Conflict`를 반환하며 최초 종료 시각을 유지한다. 세션 종료로 자동으로 닫힌 구간에도 같은 규칙을 적용한다.

### [STT-01] STT 세션 종료

**POST** `/api/v1/rooms/{roomId}/stt/sessions/{sessionId}/stop` — HOST, 강연방 소유자

Request `{ "reason": "MANUAL_STOP" }`

```json
{ "data": { "sttSessionId": 701, "roomId": 10, "status": "STOPPED", "startedAt": "2026-11-17T01:00:02Z", "endedAt": "2026-11-17T02:00:00Z", "canRecord": false } }
```

규칙: 마지막 확정 전사 결과 저장 후 종료, `MANUAL_STOP`은 `STOPPED`, 복구 불가능한 오류인 `ERROR`는 `ERROR`로 저장한다. 중복 종료 시 최초 종료 상태와 시각을 반환한다, `reason` 은 ERD 에 저장 컬럼이 없는 참고 입력.

### [STT-05] 강연 발언 및 누락 구간 조회

**GET** `/api/v1/rooms/{roomId}/stt/segments?from=&to=` — HOST, 강연방 소유자

```json
{
  "data": {
    "roomId": 10,
    "segments": [
      {
        "segmentId": 9001,
        "sessionId": 701,
        "transcript": "Redis는 메모리 기반 데이터 저장소입니다.",
        "segmentStartAt": "2026-11-17T01:00:12Z",
        "segmentEndAt": "2026-11-17T01:00:19Z",
        "receivedAt": "2026-11-17T01:00:20Z"
      }
    ],
    "gaps": [
      { "gapId": 8001, "sessionId": 701, "reason": "ERROR", "startedAt": "2026-11-17T01:25:00Z", "endedAt": "2026-11-17T01:25:15Z" }
    ]
  }
}
```

규칙: 해당 강연의 모든 STT 세션 기록을 통합 조회하고 발언 시각 순으로 정렬, 오류·누락 구간은 별도 반환, 발언이 없는 구간을 AI 로 임의 보완하지 않음, 다른 강연방 STT 기록 조회 금지.

발언과 누락 구간 모두 조회 시간 범위와 겹치는 기록 전체를 반환한다. 조회 범위에 맞춰 전사 텍스트나 기록의 시작·종료 시각을 잘라내지 않는다.

조회 범위는 시작을 포함하고 끝을 제외하는 `[from, to)`다. 종료된 기록의 시작·종료 시각이 다르면 `기록 시작 < to`이고 `기록 종료 > from`일 때 포함한다. 시작·종료 시각이 같은 기록은 해당 시각이 `from` 이상이고 `to` 미만일 때 포함한다.

열린 누락 구간도 조회 대상이다. 범위와의 겹침을 판단할 때는 조회 요청을 받은 시각까지 이어진 구간으로 취급한다. 응답의 `endedAt`은 `null`로 유지한다.

`from`과 `to`는 선택 입력이다. 둘 다 생략하면 해당 강연방의 전체 기록을 조회한다. `from`만 지정하면 하한만, `to`만 지정하면 상한만 적용한다. 둘 다 지정했을 때 `from >= to`이면 `400 Bad Request`를 반환한다. 정상 범위에 해당하는 기록이 없으면 `200 OK`와 빈 `segments`, `gaps` 배열을 반환한다.

조회는 로그인과 강연방 소유권을 검증하며 `startKey`를 요구하지 않는다. 소유자는 강연방 상태(`READY`, `LIVE`, `ENDED`)와 관계없이 조회할 수 있다. 강연 중에는 저장된 발언과 열린 누락 구간을 반환하고, 기록이 없으면 빈 배열을 반환한다.

조회 결과는 페이지 구분 없이 해당 범위의 모든 기록을 `segments`와 `gaps` 배열로 반환한다. 각 배열은 시작 시각 오름차순으로 정렬하고, 시작 시각이 같으면 해당 기록의 ID 오름차순으로 정렬한다.
