# 공통 규약

## 개요

### 서비스 목적

강연자의 실제 발언(STT)과 청중의 채팅·이해도 반응·투표 결과를 실시간으로 수집하고, AI 가 청중 의견을 주제별로 요약한다. 강연 종료 후에는 STT 발언과 청중 반응을 시간대별로 연결한 AI 회고 보고서를 제공한다.

### 주요 설계 원칙

- 강연자와 청중 모두 채팅할 수 있다.
- AI 청중 의견 요약에는 청중이 작성한 채팅만 포함한다.
- AI 는 대표 질문을 생성하지 않고, 질문·의견·요청·이해 부족 표현을 주제별로 요약한다.
- STT 는 강연자의 발언을 강연 중 지속적으로 텍스트로 변환해 저장한다.
- 강연 발언과 청중 반응은 공통 시간 구간을 기준으로 연결한다.
- 같은 시간대에 발생했다는 이유만으로 특정 발언이 이해 부족의 원인이라고 단정하지 않는다.
- 분석 결과에는 실제 원문 메시지를 연결한다.
- AI 실패가 채팅·이해도·투표 기능에 영향을 주지 않아야 한다.
- 강연 종료 후 새 채팅·이해도·투표 응답은 차단한다.

## 공통 API 규약

### 1-1. 기본 정보

| 항목 | 규격 |
| --- | --- |
| Base URL | `/api/v1` |
| WebSocket Endpoint | `/ws` |
| 데이터 형식 | JSON |
| 요청·응답 필드 | camelCase |
| DB 컬럼 | snake_case |
| 날짜·시간 | ISO-8601, UTC 오프셋 포함 |
| 강연자 역할 | HOST |
| 청중 역할 | PARTICIPANT |
| 강연 상태 | READY / LIVE / ENDED |
| 인증 방식 | 강연자 세션 쿠키 + 청중 참여 쿠키 (제안) |
| 실시간 메시지 | STOMP 주소 기준 예시 |

> 실시간 통신은 STOMP 기반으로 개발 중이다. 강연자·청중의 세션 쿠키 인증 및 강연방별 권한 검증은 후속 작업에서 적용한다.

### 1-2. 공통 성공 응답

본문이 있는 REST 성공 응답은 `data` 필드로 감싼다. 상태 코드는 각 API 항목의 `Response — <상태>` 를 따른다.

```json
{
  "data": {
    "roomId": 10,
    "status": "READY"
  }
}
```

- 목록 응답도 같은 규칙이다. `data` 안에 `messages`, `polls` 같은 배열 필드를 둔다.
- 본문이 없는 성공은 `204 No Content` 이며 본문을 보내지 않는다.
- 오류 응답은 `data` 로 감싸지 않고 §1-3 형식을 쓴다.
- STOMP 이벤트는 REST 응답과 별개로 `{ "type": "...", "data": { ... } }` 형식을 쓴다.
- 이 문서의 `Response` 예시는 모두 `data` 안쪽까지 포함해 적는다. 요청(Request) 본문은 감싸지 않는다.

### 1-3. 공통 오류 응답

```json
{
  "code": "ROOM_NOT_LIVE",
  "message": "진행 중인 강연이 아닙니다.",
  "details": null,
  "timestamp": "2026-11-17T01:00:00Z"
}
```

| HTTP 상태 코드 | 의미 |
| --- | --- |
| 400 | 입력값 오류 |
| 401 | 인증 정보 없음 또는 인증 실패 |
| 403 | 접근 권한 없음 |
| 404 | 리소스 없음 |
| 405 | 지원하지 않는 HTTP 메서드 |
| 409 | 중복 요청 또는 상태 충돌 |
| 415 | 지원하지 않는 Content-Type |
| 429 | 요청 횟수 제한 |
| 500 | 서버 내부 오류 |
| 503 | 외부 서비스 장애 |

### 1-4. 인증·접근 권한

**HOST**

- 회원가입 및 로그인한 강연자
- 자신의 강연방 생성·조회·시작·종료
- STT 관리, 투표(이해도 체크 포함) 생성·마감, 투표 결과 조회
- 강연자 대시보드 조회, AI 요약 및 회고 보고서 조회
- 채팅 송수신

**PARTICIPANT**

- 참여 코드로 비회원 입장
- 해당 강연방 채팅 송수신
- 투표 응답(이해도 체크 포함, 마감 전까지 변경 가능)
- 허용된 채팅·투표 정보 조회

강연자와 청중 모두 클라이언트에서 임의로 `userId`, `participantId`, `senderType` 을 지정해 권한을 획득할 수 없다.

### 1-5. STOMP 공통 연결 — 개발 단계

| 항목 | 설정 |
| --- | --- |
| WebSocket 연결 | `/ws` |
| 클라이언트 메시지 전송 | `/app` |
| 메시지 구독 | `/topic`, `/queue` |
| 사용자별 메시지 | `/user` |
| 허용 Origin | `app.cors.allowed-origins` |
| 운영 환경 | `prod` 프로파일에서 비활성화(인증·권한 검사 검증 후 해제 예정) |

- `/topic/`, `/queue/`, `/user/`로 직접 SEND하는 요청은 차단한다.
- 로컬 테스트용 `/app/_dev/ping` → `/topic/_dev/pong`을 지원한다.
- 연결(`/ws`)은 허용된 Origin 에서만 받는다. 연결 시점의 `HOST_SESSION` 로그인 정보와 방별 `PARTICIPANT_SESSION_{roomId}` 쿠키를 서버가 보관하고, 구독·전송 때 그 방 기준으로 검사한다.
- 구독은 허용 주소만 열려 있다: `/topic/rooms/{roomId}/chat`, `/topic/rooms/{roomId}/status`(해당 강연방의 강연자·청중만), `/user/queue/*`. 그 외는 거절한다. 구독이 거절되면 서버가 STOMP `ERROR` 를 보내고 연결을 닫는다.
- 작성자는 서버가 쿠키·로그인으로 확인한다. 본문의 `userId`, `participantId`, `sender` 등은 읽지 않는다.
- 전송 오류는 연결을 유지한 채 보낸 사람의 `/user/queue/errors` 로만 전달한다(`{ "type": "ERROR", "code", "message" }`).
