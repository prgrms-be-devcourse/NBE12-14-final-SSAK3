# 연습 모드 프론트 연동 설계

합의한 범위의 React 화면과 실제 API 연동을 구현했다. 실행 방법은 [데모 실행 안내](practice-demo.md)를 따른다.

## 합의한 범위

- React로 실제 연습 백엔드 API를 연결한다.
- 별도 로컬 데모 DB에 간단한 객관식 문제 1개를 준비한다. 기존 개발 DB와 정식 배포 데이터에 포함하지 않으며 기본 Flyway 경로에 예시 문제를 추가하지 않는다.
- 연습 시작 → 문제·보기 표시 → 답 제출 → 정답·해설 → 결과 확인을 우선 구현한다. 이력·복습 목록 화면은 다음 단계다.
- 사용자가 제공한 `cs-match-lobby-react-20261113.zip`의 React/CSS 디자인을 기준으로 한다. 흰 바탕, 파란 강조색, 남색 히어로, 카드형 구성을 활용한다.
- 첨부물의 로컬 예시 채점·가상 매칭 동작은 실제 연습 API 연동과 구분한다. 확정된 연습 규칙의 기준은 `game-rules.md`, API 계약은 `api-spec.md`다.
- 동일한 디자인으로 간단한 회원가입·로그인 화면을 제공한다. 데모 DB의 계정으로 기존 인증 API에 로그인하며 인증을 우회하지 않는다.
- 로비 구성을 유지하고 연습 모드 진입 버튼을 추가한다. 이번에 연동하지 않는 대결·프로필 상세·복습 기능은 준비 중으로 표시한다.
- 결과 화면에 다시 풀기를 제공한다. 서버의 전체 진도 초기화 후 새 연습을 시작한다.
- 새로고침하면 서버에 저장된 진행 중 연습을 이어서 보여준다. 이미 제출한 문제는 재제출하지 않고 서버 기록을 기준으로 결과를 복구한다.

## 구현과 검증

- React Router로 로비, 회원가입·로그인, 분야 선택, 문제 풀이·결과를 분리했다.
- 인증 토큰은 탭의 sessionStorage에 보관하며 로그아웃·401 응답에서 제거한다. 인증 우회나 브라우저에 포함된 JWT 비밀키는 없다.
- 표시 순서는 서버가 내려준 보기를 따르고 선택한 choiceId만 제출한다. 정답과 해설은 API 제출 결과·서버 이력에서만 가져온다.
- 새로고침·창 포커스 복귀 시 서버 상태를 다시 조회한다. 제출 응답이 유실돼도 자동 재제출하지 않고 저장된 결과를 조회한다.
- 연습 종료·전체 진도 초기화는 확인 후 요청한다. 초기화해도 이전 서버 이력은 유지된다.
- 전용 compose 프로젝트와 DB·Redis·포트를 사용한다. demo 프로파일에서만 별도 Flyway repeatable 파일의 예시 문제를 읽는다.
- Playwright에서 실제 API로 회원가입·로그인, 빈 분야, 새로고침, 정답·오답, 다시 풀기, 이어 풀기·중도 종료, 인증 만료, 제출 응답 유실 복구를 검증한다.
- 데스크톱과 폭 390px 화면을 캡처해 배치·가로 넘침을 확인했다.
