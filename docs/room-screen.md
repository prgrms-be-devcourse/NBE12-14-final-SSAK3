# SCRUM-167 강연방 화면 결정 사항

사용자가 확정안을 승인하여 생성·상세 화면을 구현했다. 백엔드 변경 없이 기존 API에 연결한다.

## 확정 사항

- 이번 범위는 강연방 생성과 강연자용 상세 화면이다.
- 상세 화면은 강연방 정보·상태와 참여 링크·QR 안내를 중심으로 구성한다.
- 같은 상세 주소에서 준비 중에는 강연을 시작하고, 진행 중에는 강연 종료·STT 녹음·AI 청중 의견 요약을 사용한다.
- 클로바노트는 색감과 글꼴의 참고 대상으로 삼으며 전체 UI 구조를 그대로 따르지 않는다.
- 화면 구조는 서비스 흐름에 맞춰 설계하며 구체적인 스타일은 아래 확정안을 따른다.
- 생성 화면 경로는 `/host/rooms/new`, 상세 화면 경로는 `/host/rooms/{roomId}`로 한다.
- 생성 성공 시 생성된 강연방 상세 화면으로 바로 이동한다.
- 상세 URL 재접속·새로고침 시 서버에서 해당 강연방 정보를 조회한다.
- 인증되지 않은 사용자는 로그인 화면으로 이동하고, 로그인 성공 후 원래 요청한 화면으로 돌아온다. 로그인 화면과의 연결은 공통 인증 화면에 맞춘다.
- 강연자 상세 화면 URL과 청중 참여 링크는 구분한다.
- 생성 폼은 제목과 설명 두 항목만 받는다. 제목은 필수·최대 200자이며 공백만 입력할 수 없다. 설명은 선택·최대 10,000자이다.
- 입력란에 글자 수와 제한을 표시하고, 제목 미입력 등 입력 오류는 해당 입력란 아래에 안내한다.
- 참여 코드와 참여 링크는 서버에서 생성하므로 입력받지 않는다.
- 생성 요청 중에는 생성 버튼을 비활성화한다. 명확한 입력 오류는 입력 내용을 유지하고 수정 후 다시 요청할 수 있게 한다.
- 시간 초과·연결 오류 등 생성 결과가 불확실하면 자동 재전송하지 않고 생성 여부를 확인하지 못했다는 안내를 표시한다. 사용자가 다시 생성하려면 중복 방이 생길 수 있음을 확인받은 뒤 요청한다.
- 위 생성 실패 처리는 백엔드 변경 없이 구현한다.
- 상세 화면의 ‘청중 초대’ 메뉴에서 참여 코드, 참여 링크 복사, QR 크게 보기를 제공한다.
- 확대된 QR을 닫으면 초대 패널로 돌아온다. QR 이미지 다운로드는 이번 범위에서 제외한다.
- READY·LIVE 상태에서는 참여 링크와 QR을 제공하고 각각 준비 중·진행 중 안내를 표시한다.
- ENDED 상태에서는 참여 링크·QR을 숨기고 새로운 참여가 불가능함을 안내한다. 제목·설명·생성 시각은 유지하고 시작·종료 시각은 값이 있을 때만 표시한다.
- READY·LIVE 상태에서는 상세 화면이 보이는 동안 5초마다 강연방 상태를 조회한다. 탭이 비활성화되면 주기 조회를 멈추고 돌아오면 즉시 조회한다.
- ENDED 확인 시 참여 링크·QR을 숨기고 열린 QR 크게 보기도 닫으며 주기 조회를 중단한다.
- 상태 조회 실패 시 상태 확인 실패를 안내하고 참여 안내를 잠시 숨긴다. 사용자가 누를 수 있는 '다시 확인' 버튼을 제공한다.
- 강연방 정보 조회는 성공했지만 참여 정보 조회만 실패하면 강연 정보는 유지한다. 참여 안내 영역에 오류와 '다시 불러오기' 버튼을 표시하고 기존 방의 참여 정보만 재조회한다. 방을 다시 생성하지 않는다.
- 인증·권한 오류는 부분 실패 처리보다 우선한다. 401은 기존 강연 정보·QR을 제거하고 로그인 화면으로 이동한 뒤 로그인 성공 시 원래 화면으로 복귀한다. 403은 기존 정보를 제거하고 권한 없음, 404는 기존 정보를 제거하고 강연방을 찾을 수 없다는 안내를 표시한다.
- 권한 없음·방 없음 화면에서도 공통 메뉴의 ‘새 강연방’으로 이동할 수 있다. 서버·연결 오류는 기존 강연 정보를 유지하되 최신 상태를 확인하지 못했음을 표시하고 '다시 확인' 버튼을 제공한다. 참여 안내는 상태 재확인 전까지 숨긴다.

- 작성 중 로그인 만료에 대비해 제목·설명을 계정과 연결하여 같은 탭의 sessionStorage에 임시 보관한다. 같은 계정으로 로그인하면 복원하고 다른 계정이면 삭제한다.
- 생성 성공 시 임시 내용을 삭제한다. 로그인 후 내용을 복원해도 자동 생성하지 않고 사용자가 다시 생성 버튼을 눌러야 한다.

- 강연자 홈과 상세 화면은 Pretendard를 사용한다. 본문은 흰색 바탕에 짙은 회색(#1E2834), 메뉴는 밝은 회색(#F6F8FA), 선택한 메뉴는 연한 파란색(#E5EFFD), 주요 버튼은 청록색(#007E78)으로 표시한다.
- 제목은 굵고 크게, 본문은 약 16px로 구성하며 그림자·그라데이션은 최소화한다. 오류와 강연방 상태는 색상뿐 아니라 문구로도 구분한다.

- 생성 화면은 가운데 제한된 폭의 폼에 제목·설명·생성 버튼 순으로 배치한다.
- 강연방 상세 화면 상단에 제목, 상태, 강연 시작·종료 버튼을 표시한다.
- 종료된 방에서는 강연 정보와 AI 요약을 유지한다. ‘저장된 발언 보기’를 펼치면 해당 방의 모든 세션에서 저장된 발언과 실제 누락 구간을 시작 시각순으로 읽을 수 있다.
- QR 크게 보기는 배경을 가리는 팝업으로 열며 닫기 버튼과 Esc로 닫을 수 있게 한다.

- 같은 탭·같은 계정이라면 새로고침하거나 생성 화면에 다시 들어와도 초안을 복원하고 복원 안내를 표시한다.
- '입력 초기화' 버튼은 확인 후 입력 내용과 임시 저장 내용을 삭제한다. 생성 성공 시에도 초안을 삭제한다.
- 생성 결과가 불확실했던 상태는 초안과 함께 저장·복원하여 새로고침 이후에도 중복 생성 주의를 유지한다.

- 최초 구현은 STT 확인용 로그인 폼을 재사용했다. 이후 사용자가 승인한 인증 화면 작업에서 `/login`으로 교체했다. 인증 화면의 동작과 검증은 `docs/host-flow-screen.md`에 기록한다.

## 강연자 메뉴와 녹음 중 이동

- 새 디자인의 적용 범위는 강연자 홈(진행 중인 강연방 목록과 생성 폼)과 강연방 상세(준비·진행·종료 상태)로 한정한다.
- 공통 메뉴는 ‘홈’과 ‘새 강연방’이다. ‘홈’은 홈의 진행 중인 강연방 목록으로 이동하고, ‘새 강연방’은 홈의 생성 폼으로 이동해 제목에 포커스를 둔다. 작성하던 초안은 유지한다. 녹음 시작·중지와 강연 종료 버튼은 강연방 상세 본문에 둔다.
- 녹음 중 ‘홈’이나 ‘새 강연방’을 누르면 이동 여부를 한 번만 확인한다. 확인창이 열린 동안과 ‘계속 녹음하기’를 선택한 뒤에도 녹음은 이어진다. ‘청중 초대’는 이동 확인 없이 바로 열며 녹음을 계속한다.
- ‘이동하기’를 누르면 음성 인식을 일시정지한다. 인식이 멈추는 과정에서 마지막으로 확정된 발언까지 포함해, 남은 확정 발언 각각이 브라우저 또는 서버에 저장됐는지 확인한다. 한 곳에라도 저장된 발언은 이동을 막지 않는다. 양쪽 모두 저장을 확인하지 못한 발언이 있으면 상세 화면에서 저장을 재시도하고, 모두 확인되는 즉시 추가 확인창 없이 처음 선택한 목적지로 이동한다. 강연방은 진행 상태를 유지한다.
- 저장을 기다리는 동안 ‘강연에 머무르기’를 누르면 예정된 이동만 취소하고 발언 저장은 계속한다. 이후 저장이 성공해도 상세 화면에 머물며, 강연자가 ‘녹음 재개’를 눌러야 음성 인식을 다시 시작한다.
- PC에서는 왼쪽 메뉴바의 ‘청중 초대’를 누르면 메뉴 옆에 팝업이 열린다. 팝업은 본문 위에 떠서 읽던 줄과 스크롤 위치를 유지한다. 폭 760px 이하에서는 상단 메뉴(☰)에서 ‘청중 초대’를 선택하면 메뉴가 닫히고 화면 아래에서 초대 패널이 올라온다.
- 패널은 기본으로 접어 두고 참여 코드, 참여 링크 복사, QR 크게 보기를 한곳에서 제공한다. 패널을 열고 닫는 동안 강연 화면과 진행 중인 녹음을 유지한다.
- 준비 중이거나 진행 중인 방에서만 초대 메뉴를 표시한다. 방이 종료되면 열린 초대 패널과 확대된 QR을 닫는다.

## 홈에서 진행 중이거나 준비 중인 강연방 열기

강연자는 홈에서 자신이 만든 진행 중(`LIVE`) 강연방과 준비 중(`READY`) 강연방을 찾아 기존 상세 화면을 다시 열 수 있다.
홈에는 위에서부터 ‘진행 중인 강연’, ‘준비 중인 강연’, ‘새 강연방’ 생성 폼 순서로 배치한다.
‘준비 중인 강연’은 방을 만든 시각이 가장 최근인 순서로 표시한다.
각 방의 제목과 생성 일시(한국 시간)를 표시한다. ‘강연방 열기’를 누르면 해당 방의 기존 상세 화면으로 이동한다.
홈에 처음 들어오면 서버는 최근에 만든 준비 중인 방을 최대 3개 반환하고, 더 조회할 방이 있는지도 알려준다. 다음 방이 있으면 ‘더 보기’를 표시하고, 누를 때마다 서버에서 다음 방을 최대 3개 받아 기존 목록 끝에 추가한다.
‘더 보기’ 요청이 서버·연결 오류로 실패하면 이미 표시한 목록을 유지한다. 목록 끝에 오류 안내와 ‘다시 시도’를 표시하고, 누르면 마지막으로 표시한 방 다음부터 최대 3개만 다시 요청한다.
다른 탭에서 같은 홈 탭으로 돌아오면 펼쳐 둔 개수만큼 최신 목록을 보여준다. 홈에 새로 진입하거나 페이지를 새로고침하면 최근 3개부터 다시 보여준다.
조회에 성공했을 때 준비 중인 방이 1개 이상이면 목록을 표시하고, 0개이면 제목을 포함한 해당 영역 전체를 숨긴다.

‘진행 중인 강연’ 목록은 로그인한 강연자가 소유한 `LIVE` 강연방만 조회한다. 방이 하나여도 홈에 머물며, 강연자가 원하는 방의 ‘강연으로 돌아가기’를 눌렀을 때만 해당 방의 기존 상세 화면으로 이동한다.
진행 중 목록은 강연 시작 일시가 최신인 순으로 정렬하고, 각 방의 제목과 시작 일시(한국 시간)를 함께 표시한다. 조회가 성공해 진행 중인 방이 0개이면 해당 위치에 ‘현재 진행 중인 강연이 없습니다’ 한 줄만 표시한다.
홈에 진입하거나 다른 탭에서 홈 탭으로 돌아올 때만 ‘진행 중인 강연’과 ‘준비 중인 강연’ 목록을 함께 자동 갱신한다. 그사이에 시작된 방은 갱신 후 ‘진행 중인 강연’ 목록에만 표시한다.
목록에서 선택한 방은 기존 상세 화면에서 상태를 다시 조회한다. 그사이에 방이 종료됐으면 해당 방의 종료 화면을 바로 표시한다.
서버·연결 오류로 첫 조회에 실패하면 ‘강연방 목록을 불러오지 못했습니다’와 ‘다시 불러오기’를 한 번 표시한다. 갱신에 실패하면 마지막으로 확인한 두 목록과 펼친 개수를 유지하고 갱신 실패를 한 번 안내한다. ‘다시 불러오기’는 두 목록만 함께 재조회하며, 작성 중인 새 강연방의 제목과 설명은 유지한다.

## 준비 중인 강연방 삭제와 청중 참여 화면

청중은 로그인 없이 `/join/{joinCode}`에서 닉네임으로 입장한다. 삭제 시 `/participation-ended/unavailable`, 정상 종료 시 `/participation-ended/ended`로 이동한다. 종료 화면을 새로고침해도 해당 사유가 표시된다.
청중이 대기하는 동안 강연이 시작되면 같은 화면에서 ‘강연 진행 중’으로 자동 전환하고 닉네임을 유지한다. 이미 진행 중인 방에 닉네임으로 입장하면 곧바로 ‘강연 진행 중’을 표시한다.
입장 가능한 방에서 새로고침하거나 같은 브라우저로 초대 링크를 다시 열면 해당 방의 참여 세션을 확인한다. 세션이 유효하면 기존 참여자와 닉네임으로 바로 복귀하고, 세션이 없거나 만료된 경우에만 닉네임 입력 폼을 표시한다.
입장 요청의 결과가 불확실하면 입력한 닉네임을 유지하고 ‘입장 다시 시도’를 표시한다. 청중이 이 버튼을 누르면 같은 방에 같은 닉네임과 최초 요청의 입장 키(`Idempotency-Key`)로 다시 요청한다.
서버가 입장 키 만료를 확인하면 닉네임을 유지하고 ‘새로 입장’을 표시한다. 방이 입장 가능한 상태에서 청중이 이 버튼을 눌렀을 때만 새 키를 발급해 요청한다.
첫 입장 요청을 보내기 전에 같은 탭에 방별로 닉네임과 입장 키를 임시 보관한다. 새로고침하면 세션을 먼저 확인한다. 유효한 세션이 있으면 바로 복귀하고 임시 정보를 지운다. 입장 가능한 방에서 세션이 없고 보관한 시도가 있으면 닉네임과 키를 복원하고, ‘입장 다시 시도’를 눌렀을 때만 그 요청을 다시 보낸다.
실시간 연결이 끊기면 기존 청중 화면에 ‘연결 확인 중’을 표시한다. 재연결 시 서버에서 방 상태를 다시 확인해 대기·진행 화면을 복원하거나, 정상 종료·삭제에 맞는 참여 종료 화면으로 이동한다.
강연자는 홈에서 자신이 만든 준비 중(`READY`) 강연방을 삭제할 수 있다. 이미 입장한 청중이 있거나 과거 입장 기록이 있어도 삭제할 수 있다.
강연자가 삭제를 확정하면 해당 강연방과 그 방의 청중 입장 기록을 함께 영구 삭제한다.
서버에서 삭제가 완료되면 해당 방에 접속 중인 청중에게 실시간으로 알린다. 청중 화면은 삭제 알림을 받는 즉시 “더 이상 참여할 수 없는 강연방입니다”라고 안내하고 해당 방에서 자동으로 퇴장시킨다.
청중은 방 삭제 또는 강연 정상 종료 시 로그인 없이 볼 수 있는 같은 ‘참여 종료’ 화면으로 이동한다. 방 삭제 시에는 “더 이상 참여할 수 없는 강연방입니다”, 정상 종료 시에는 “강연이 종료되었습니다”라는 안내를 계속 표시한다. 이미 정상 종료된 방의 초대 링크를 열어도 닉네임 입력 없이 정상 종료 안내를 바로 표시한다.
PC와 모바일 모두 준비 중인 방의 ‘강연방 열기’ 옆에 `⋯` 메뉴를 둔다. 이 메뉴에서 ‘강연방 삭제’를 선택하면 해당 방의 삭제 확인창을 연다.
삭제 확인창에는 선택한 방의 제목과 생성 일시(한국 시간)를 표시하고 기본 포커스를 ‘취소’에 둔다. ‘영구 삭제’를 선택했을 때만 서버에 삭제 요청을 보낸다.
서버가 삭제 요청을 처리할 때 방이 이미 시작됐다면 방과 청중 입장 기록을 보존한다. 확인창을 닫고 홈에서 삭제할 수 없는 이유를 안내한 뒤, 진행 중인 강연과 준비 중인 강연 목록을 함께 갱신한다.
삭제 결과가 불확실하면 해당 방 ID로 현재 상태를 조회한다. 방이 없으면 그 사실을 안내하고 두 목록을 갱신한다. 여전히 준비 중이면 강연자가 직접 ‘영구 삭제’를 다시 선택할 수 있다. 상태 조회도 실패하면 ‘상태 다시 확인’으로 조회를 재시도하며, 삭제 요청을 자동으로 반복하지 않는다.
삭제 성공을 확인하면 해당 방을 홈 목록에서 즉시 제거한다. 준비 중인 방을 펼친 개수와 작성 중인 새 강연방 제목·설명을 유지하며 두 목록을 갱신한다. 갱신에 실패해도 삭제한 방은 다시 표시하지 않는다. ‘다시 불러오기’는 두 목록만 재조회한다.

## 강연자 화면의 AI 요약과 채팅

- PC에서는 중앙에 AI 청중 의견 요약, 오른쪽에 같은 방의 채팅을 나란히 표시한다.
- 모바일에서는 ‘AI 요약’과 ‘채팅’ 탭을 제공하고, 처음에는 ‘AI 요약’을 표시한다. 강연 진행 중에는 녹음 버튼과 저장 상태를 탭 위에 둬 어느 탭에서든 확인할 수 있게 한다.
- 강연이 끝나면 채팅 내역은 읽기 전용으로 남긴다. [채팅 내역과 전송 규칙](api/chat.md)

## 실행과 연동

- 백엔드와 프론트 개발 서버 실행 후 `/host/rooms/new`로 접속한다. 생성 성공 시 `/host/rooms/{roomId}`로 이동한다.
- 홈은 `GET /api/v1/rooms/home`으로 두 목록을 함께 불러오고, ‘더 보기’는 `GET /api/v1/rooms/ready`에 직전 응답의 커서를 보내 다음 방을 가져온다. [강연방 API 명세](api/room.md)
- 인증되지 않은 경우 `/login`으로 이동한다. `returnTo`는 이 두 강연방 경로만 허용한다. SCRUM-98 공통 구조 통합 시 이 복귀 정책을 유지한다.
- STT 확인용 화면은 `/dev/stt`, 보고서 미리보기는 `/preview/reports`에서 확인한다. `/`은 정식 인증 진입 화면이다.
- 진행 화면의 AI 요약은 바로 읽을 수 있고, 최근 발언은 접어 둔다. 녹음 시작·중지와 저장 상태는 항상 표시한다. 강연을 시작해도 마이크는 강연자가 녹음 시작을 눌러야 켜진다.
- 강연 종료 확인창이 열려 있는 동안 녹음은 계속된다. 확정하면 마지막 발언의 서버 저장과 STT 세션 종료를 확인한 뒤 강연방을 닫는다. 녹음 중지만 선택하면 방은 계속 열린다.
- 시작·종료 응답을 놓치면 방 상세로 상태를 먼저 확인한다. 새로고침으로 복구한 종료 작업은 강연자가 ‘강연 종료 계속하기’를 눌러야 방을 닫는다. 상태별 재시도 규칙은 [강연방 API 명세](api/room.md)에 기록한다.
- 서버 `/rooms`, `/rooms/{roomId}`, `/rooms/{roomId}/invitation`, `/auth/me` 및 기존 CSRF 처리 API 클라이언트를 사용한다. QR은 서버 `qrText`로 브라우저에서 생성하며 외부 QR 서비스로 전달하지 않는다.
- 폰트는 패키지에 포함된 Pretendard를 자체 제공한다. 공통 메뉴와 본문 색상은 강연자 홈·상세 화면의 `.room-app.host-shell` 안에서 적용한다.
- 상태 조회 실패 시 자동 조회도 중단하고 수동 재확인으로 재개한다. 요청이 겹치지 않도록 이전 조회 완료 후 다음 조회를 예약한다.
- 초안 저장소 사용 불가 시 복원할 수 없음을 화면에 안내한다. 결과 불확실 상태는 생성 요청 전 저장하여 요청 도중 새로고침에도 유지한다. 서버 오류도 결과 불확실로 취급한다.
- 기본 브라우저 테스트는 API 응답을 모의 처리한다. 실제 서버와 테스트 전용 DB로 두 창의 삭제·정상 종료를 확인하는 방법은 [테스트 안내](testing.md#강연자와-청중의-두-창-통합-테스트)에 있다.

## 검증

- `npm test`: 기존 STT 단위 테스트.
- `npx playwright test`: 생성·로그인 복귀·계정별 초안·응답 유실·상태 갱신·부분 실패·권한 오류·QR 팝업·모바일 화면 및 기존 STT/보고서 회귀 테스트.
- `npm run build`: 운영 빌드.
- 강연자 메뉴 검증은 PC와 모바일 크기의 Chromium에서 실행한다. 초대창을 닫을 때 포커스가 돌아오는 위치, 녹음 중 메뉴 이동과 저장 재시도, 이동 취소 후 지연된 저장 응답을 확인한다.
- 백엔드 최초 실행은 로컬 테스트 계정·DB 미준비로 인증 거부(SQL 1045)가 발생했다. 테스트 전용 `react_test` 계정·DB와 Git 제외 파일 `.env.test`를 준비한 뒤 `gradlew.bat build --rerun-tasks`로 전체 재실행하여 빌드 성공을 확인했다. 개발 DB `react`와 백엔드 코드는 변경하지 않았다.
- 두 창 통합 테스트는 브라우저 세션을 분리해 청중이 실제 방별 WebSocket 이벤트를 수신하고 종료 화면으로 이동하는지 검증한다.
- 후속 확인에서 `AiAnalysisFinalizationRepositoryIntegrationTest` 단독 재실행 시 기존 종료 방이 `findCandidates(5)`의 앞 5개를 차지하는 데이터 격리 문제를 재현했다. 테스트 전·후 Flyway 초기화와 정확한 테스트 DB 이름 검증을 추가했다. 수정 후 단독 2개 → 전체 빌드 205개 → 단독 재실행 2개가 모두 통과했다. 공유 테스트 DB를 사용하는 실행은 순차로 수행하며, 자세한 규칙은 `docs/testing.md`를 따른다.
