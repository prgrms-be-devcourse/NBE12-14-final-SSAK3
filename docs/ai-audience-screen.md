# SCRUM-154·155 AI 청중 질문·의견 요약 영역

사용자가 확정안을 승인하여 중앙 요약 영역과 실제 API에 연결하는 확인용 페이지를 구현했다. 백엔드와 DB 스키마는 변경하지 않았다.

## 참고 자료

- Figma: https://www.figma.com/design/nJBBDjU7F71kgdmOZi7LUH/?node-id=0-1
- API: `docs/api/ai-chat.md`
- Figma의 Presenter 화면은 왼쪽 이해도·투표, 중앙 AI 질문·의견 분석, 오른쪽 채팅·발언 기록으로 구성된다.

## 확정 사항

- 이번 구현 범위는 Presenter 화면 중앙에 들어갈 AI 요약 카드와 카드 안의 근거 원문 펼치기다.
- 이해도·투표·실시간 채팅·발언 기록 등 다른 대시보드 영역은 이번 범위에 포함하지 않는다.
- 기본 화면은 최신 분석을 중심으로 표시하고, 이전 분석은 '이전 분석 보기'를 펼쳐 확인한다. 모든 30초 구간을 기본 화면에 계속 나열하지 않는다.
- 이전 분석은 최신 시간대부터 표시하고, 같은 분석 구간의 요약 카드를 함께 묶는다.
- 서로 다른 분석 구간의 비슷한 주제는 합치지 않고 별도 카드로 유지한다.
- 새 분석 구간이 COMPLETED이고 요약 카드가 없으면, 기존에 표시하던 마지막 요약 카드를 원래 분석 시간대와 함께 유지한다. 최신 구간에는 '이 구간에는 표시할 새 요약이 없습니다'라고 별도로 안내하며, 이전 카드를 최신 구간의 결과처럼 표시하지 않는다.
- 이전 요약도 없으면 새 요약이 없다는 안내만 표시한다.
- 최신 구간이 PENDING·PROCESSING·FAILED여도 기존 요약 카드와 원문 보기를 유지하고, 기존 카드의 원래 시간대를 표시한다. 최신 구간에는 각각 분석 대기·분석 중·요약 실패 안내를 별도로 표시한다. 기존 요약이 없으면 상태 안내만 표시한다.
- 분석 실패를 청중 의견이 없는 상태로 표시하지 않으며, 이번 화면에는 분석 재실행 버튼을 제공하지 않는다.
- 화면 진입 시 분석 결과를 즉시 조회하고, 화면이 보이는 동안 조회 완료 후 5초마다 다시 조회한다. 이전 요청과 다음 요청이 겹치지 않게 한다.
- 다른 탭으로 이동하면 주기 조회를 멈추고 돌아오면 즉시 조회한다. 갱신 중에도 기존 카드를 유지하며 전체 로딩 화면으로 교체하지 않는다.
- 주기 조회는 서버에 저장된 분석 결과를 읽는 동작이며, LLM 분석을 새로 실행하지 않는다.
- 원문을 펼치지 않은 상태에서 새 요약이 도착하면 최신 요약 카드로 자동 갱신한다.
- 원문을 펼친 동안에는 새 요약이 도착해도 현재 카드를 자동 교체하지 않고, 원래 시간대와 함께 유지하며 '새 요약이 있습니다 · 보기' 버튼을 표시한다.
- 사용자가 '새 요약 보기'를 누르면 최신 요약으로 전환하고 기존 원문 펼침을 닫는다.
- 여러 카드의 원문을 동시에 펼칠 수 있다. 다른 카드를 열어도 기존 원문은 닫지 않으며, 카드별 '원문 접기'로 개별적으로 닫는다.
- 근거 원문은 해당 카드의 '원문 보기'를 처음 눌렀을 때 조회하고, 카드 내부에 로딩 상태를 표시한다.
- 원문 조회에 성공한 결과는 같은 화면에 머무는 동안 메모리에 보관하여 접었다 다시 펼칠 때 재사용한다. 새로고침하거나 다른 강연방으로 이동하면 다시 조회한다.
- 원문 조회만 연결·서버 오류로 실패하면 요약은 유지하고 해당 카드에 '원문을 불러오지 못했습니다' 안내와 '다시 시도' 버튼을 제공한다. 인증·권한 오류는 아래 공통 정책을 우선 적용한다.
- 분석 목록은 최근 10개 구간으로 시작한다. '이전 분석 보기' 안의 '더 보기'를 누르면 최근 50개 구간까지 조회 범위를 넓힌다. 개수는 카드 수가 아닌 분석 구간 수이며, 카드가 없는 구간과 실패한 구간도 포함한다.
- 현재 API가 지원하는 최대 50개 구간보다 오래된 기록을 조회하는 기능은 이번 범위에서 제외한다.
- 분석 목록 조회 중 연결·서버 오류가 발생하면 기존 카드와 이미 불러온 원문을 유지하되, 최신 결과를 확인하지 못해 마지막으로 불러온 내용을 표시 중임을 안내한다. 자동 조회를 중단하고 '다시 연결' 버튼을 제공한다.
- '다시 연결'을 누르면 즉시 조회하고, 성공하면 5초 주기 자동 갱신을 재개한다. 처음 조회부터 실패했다면 오류 안내와 버튼만 표시한다. 이는 AI 분석 자체의 FAILED 상태와 구분한다.
- 강연 종료 후에도 화면이 보이는 동안 동일한 5초 주기 조회를 유지한다. 현재 조회 API에는 강연 전체 분석 완료를 나타내는 값이 없어, 종료 상태만으로 조회를 중단하지 않는다.
- 종료 후에도 탭 비활성화·화면 이탈 시 주기 조회를 멈추며, 연결·서버 오류 시에는 기존 '다시 연결' 정책을 적용한다. 전체 분석 완료 상태가 API에 제공되면 완료 시 자동 중단하도록 개선할 수 있다.

## 확인용 화면

- 실제 API에 연결하는 확인용 페이지를 `/dev/rooms/{roomId}/ai`에 둔다.
- 상단에는 강연 제목과 '강연방 상세로 돌아가기'를 표시하고, 본문에는 이번 범위의 AI 요약 카드·원문 펼치기를 배치한다.
- 강연자 로그인과 강연방 소유권 검증은 그대로 적용한다. 확인용 경로라고 인증·인가를 우회하지 않는다.
- 개발 환경의 강연방 상세에만 'AI 요약 확인' 진입 링크를 표시한다.
- 분석 데이터가 없는 방에는 빈 상태를 표시한다. 이후 Presenter 대시보드에 요약 영역을 통합한다.
- 최초 진입·새로고침 시 최근 10개 구간에 표시할 요약이 없으면 최근 50개까지 추가 조회하여, 요약 카드가 있는 가장 최근 COMPLETED 분석을 찾는다.
- 찾은 요약은 원래 분석 시간대와 함께 '마지막 요약'으로 표시한다. 50개 구간 안에도 없으면 '최근 조회 범위에 표시할 요약이 없습니다'라고 안내하며, 강연 전체에 의견이 없었다고 단정하지 않는다.
- 자동 탐색 또는 '더 보기'로 50개까지 조회한 뒤에는 해당 화면에서 50개 범위로 갱신한다. 새로고침하면 다시 최근 10개부터 시작한다.

## 카드·원문 표시

- 요약 카드에는 주제 제목, 유형, 분석 시간대, 'AI 요약'으로 구분한 요약 내용, 관련 원문 건수, '원문 보기'를 표시한다.
- 유형은 서버가 반환한 하나의 category를 질문(QUESTION), 의견(OPINION), 요청·제안(REQUEST), 이해 부족 표현(CONFUSION), 혼합(MIXED)으로 표시한다. 프론트에서 여러 유형을 추론하여 추가하지 않는다.
- 펼친 원문에는 청중 닉네임, 메시지 시각, 실제 채팅 내용을 표시하며 AI 요약과 명확히 구분한다.
- 관련 원문 건수는 메시지 수이며 참여자 수로 표시하지 않는다.
- 분석 시간대와 메시지 시각은 한국 시간(KST)으로 표시한다.

## 인증·권한 오류

- 인증·권한 오류는 연결·서버 오류 처리보다 우선한다. 분석 목록 또는 원문 조회에서 401·403이 발생하면 화면의 요약·원문과 메모리에 보관한 원문을 지우고 자동 조회를 중단한다.
- 401은 로그인 화면으로 이동하고 로그인 성공 후 원래 화면으로 복귀하여 서버에서 다시 조회한다.
- 403은 '이 강연방을 조회할 권한이 없습니다'라고 안내한다.
- 분석 목록 조회에서 404가 발생하면 기존 내용을 지우고 자동 조회를 중단하며 '강연방을 찾을 수 없습니다'라고 안내한다.
- 원문 조회에서만 404가 발생하면 강연방 전체가 없다고 단정하지 않는다. 해당 카드에 '근거 원문을 찾을 수 없습니다'라고 안내하고 나머지 요약은 유지한다.

## 구현·확인 방법

- `frontend/src/ai/feed.js`: 한 강연방의 조회 주기, 마지막 요약 유지, 원문 캐시와 인증 오류 처리를 담당한다. 화면 이탈·방 변경·권한 오류 뒤 늦게 도착한 응답은 폐기한다.
- `AudienceAnalysisPanel.jsx`: 대시보드에 통합할 요약·이전 분석·근거 원문 영역이다.
- `AudienceAnalysisPage.jsx`: 확인용 페이지에서 로그인·강연 정보·방별 데이터 수명을 연결한다.
- 기존 Pretendard 글꼴과 회색 배경·초록색 포인트를 사용하며 모바일에서도 가로 스크롤 없이 볼 수 있다.
- 원문을 전부 접으면 대기 중인 최신 결과를 반영한다. '이전 분석 접기'는 그 안의 원문도 접는다. '더 보기'는 읽던 원문을 유지하면서 과거 구간을 추가한다.
- `/dev/rooms/{roomId}/ai`는 실제 조회 API를 사용한다. 개발 환경 전용인 것은 강연방 상세의 진입 링크이며, 확인용 페이지 자체도 서버의 인증·소유권 검사를 받는다.
- 프론트와 백엔드를 실행하고 강연자로 로그인한 뒤, 자신의 강연방 상세에서 'AI 요약 확인'을 누른다. 저장된 분석이 있는 방에서 카드와 원문을 확인할 수 있다. 없는 방에는 빈 상태를 표시하며 테스트용 분석 데이터를 자동 생성하지 않는다.

```bash
cd frontend
npm test
npm run build
npx playwright test --workers=4
```

- `npm run build` 통과.
- `backend/gradlew.bat build` 성공. 백엔드 변경이 없어 `test`는 UP-TO-DATE였으며 이번 작업에서 DB 테스트를 새로 실행한 것은 아니다.
- 위 회귀 테스트는 API 응답을 모의한다. 실제 LLM 호출은 수행하지 않았다.

## 로컬 샘플 확인

- 사용자 요청으로 로컬 `react` DB의 `test2` 강연방(ID 5)에만 샘플을 추가했다. 같은 이름의 ID 4 방은 변경하지 않았다.
- 샘플 청중 3명, 채팅 14건, 분석 구간 12개(완료 11개·실패 예시 1개), 요약 카드 6개를 추가했다. 최신 구간에는 카드 3개가 있으며, '이전 분석 보기 → 더 보기'로 가장 오래된 카드까지 확인할 수 있다.
- 주제·요약·닉네임·채팅에 샘플 표시를 붙였으며, 분석의 모델명은 `sample-manual-no-llm`이다. 실제 모델 생성 결과가 아닌 화면 확인용 합성 데이터다.
- 방은 READY로 유지하고 시작·종료 시각은 변경하지 않았다. 샘플 추가 과정에서 LLM을 호출하지 않았다.
- 실제 로컬 서버의 로그인 세션으로 최근 10개·50개 분석 및 최신 카드의 근거 원문 조회를 확인했다. 실제 프론트에서도 로그인 → 방 5의 AI 화면 → 원문 펼치기 → 이전 분석 더 보기를 확인했다.
- 샘플은 해당 로컬 DB에만 들어 있으며, Git pull이나 서버 실행으로 자동 삽입되지 않는다. Flyway 마이그레이션은 추가하지 않았다.
