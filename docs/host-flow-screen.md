# 강연자 전체 흐름 화면 — 구현 전 협의

기존 강연방 생성·상세 화면 작업과 구분하여 다음 화면 작업의 결정 사항을 기록한다.
강연자 전체 흐름을 목표로 하되, 백엔드 API가 구현된 화면부터 실제 API에 연결하여 순차 구현한다.
협의와 최종 구현 승인을 마쳤으며 아래 인증 화면을 구현했다.

## 확정 사항

- 강연자 흐름을 먼저 완성하고 청중 입장·채팅·투표 화면은 다음 작업으로 진행한다.
- 대상 흐름: 로그인·회원가입 → 내 강연방 목록 → 강연방 생성·상세 → 강연 진행 → 종료 → 보고서.
- 이미 구현된 생성·상세·STT·보고서 화면을 활용한다.
- 샘플 미리보기로 전체 흐름을 새로 만드는 제안은 채택하지 않았다. API가 없는 기능은 이번에 새로 구현하지 않는다.

## 로그인·회원가입 작업 확인

- 원격 develop `e30c64c` 기준 정식 로그인·회원가입 화면은 없고 STT 확인용 로그인 폼만 존재한다. 열린 PR도 없다.
- Jira SCRUM-100은 백한비 담당·검토 중, SCRUM-98은 백한비 담당·진행 중이다. 저장소에 공유되지 않은 로컬 작업의 존재 여부는 확인되지 않았다.
- 백엔드 회원가입·로그인·내 정보·로그아웃 API는 구현되어 있다. 회원가입은 계정 생성만 하며 인증 세션을 만들지 않는다.

## 현재 작업 범위와 승인 상태

- 다음 구현 범위는 정식 로그인·회원가입 화면 및 기존 강연방 생성·상세 화면의 인증 진입·로그아웃 연결이다.
- 강연방 목록·강연 시작/종료 등 API가 없는 기능은 이번 구현에서 제외한다.
- 인증 화면의 주요 동작·구성을 확정하고 구현·테스트를 수행했다.

## 인증 화면 확정 사항

- 회원가입 성공 시 가입 완료 안내와 함께 이메일이 채워진 로그인 화면으로 이동한다. 자동 로그인하지 않는다.
- 비밀번호는 로그인 화면으로 전달하거나 저장하지 않는다.
- 원래 돌아갈 강연방 주소가 있었다면 회원가입·로그인 흐름에서도 유지하여 로그인 성공 후 해당 화면으로 복귀한다.
- 회원가입 폼은 이름·이메일·비밀번호·비밀번호 확인 네 항목으로 구성한다. 이름은 필수·최대 100자, 이메일은 필수·이메일 형식·최대 255자이다.
- 비밀번호는 현재 백엔드 기준인 최소 8자·최대 72바이트를 검사하고 추가적인 문자 조합 규칙을 도입하지 않는다. 비밀번호 확인은 일치 여부만 프론트에서 검사하며 서버로 보내지 않는다.
- 로그인 성공 후 유효한 원래 강연방 주소가 있으면 해당 화면으로 복귀한다. 복귀 주소가 없으면 `/host/rooms/new`로 이동한다. 생성 화면으로 복귀하는 경우 기존 계정별 초안 복원 규칙을 유지한다.
- 향후 강연방 목록 API·화면이 완성되면 기본 이동 위치 변경을 검토한다.
- 입력 오류는 최초 진입 시 표시하지 않고 입력란에서 벗어날 때 검사한다. 오류가 표시된 항목은 수정 중 다시 검사하며 유효해지면 오류를 제거한다.
- 제출 시 전체 입력을 재검사하고 오류가 있으면 서버 요청 없이 첫 오류 입력란으로 포커스를 이동한다.
- 로그인 정보 불일치는 '이메일 또는 비밀번호를 확인해 주세요'로 안내한다. 이메일 중복 가입은 이메일 아래 안내와 로그인 이동 링크를 제공한다.
- 서버·연결 오류는 자동 재전송 없이 사용자가 재시도한다. 회원가입 응답 유실 시 가입 여부를 확인하지 못했음을 안내하고 로그인 이동·가입 재시도를 제공한다.
- 요청 중 제출 버튼을 비활성화한다. 실패 시 현재 화면의 입력을 유지하되 비밀번호는 브라우저 저장소에 저장하지 않는다.
- 로그인·회원가입 화면 진입 시 `/auth/me`로 로그인 상태를 확인한다. 인증된 경우 유효한 복귀 주소 또는 강연방 생성 화면으로 바로 이동하고, 미인증인 경우 폼을 표시한다.
- 로그인 상태 확인 중에는 확인 중 안내를 표시한다. 서버·연결 오류를 미인증으로 간주하지 않고 별도 안내와 '다시 확인' 버튼을 제공한다.
- 강연방 생성·상세 화면 상단 오른쪽에 사용자 이름과 로그아웃 버튼을 제공한다. 작성 중인 초안이 있으면 직접 로그아웃 시 삭제됨을 확인받는다.
- 서버 로그아웃 성공 시 해당 계정의 강연방 초안을 삭제하고 로그인 화면으로 이동한다. 로그인 만료 후 재인증 시 초안을 복원하는 기존 정책과 구분한다.
- 로그아웃 요청의 단순 연결 오류는 성공으로 단정하지 않고 안내와 재시도를 제공한다.
- 로그인 `/login`과 회원가입 `/signup`을 별도 페이지로 구성한다. 로그인 폼은 이메일·비밀번호·로그인 버튼·회원가입 링크 순서, 회원가입 폼은 이름·이메일·비밀번호·비밀번호 확인·회원가입 버튼·로그인 링크 순서로 구성한다.
- 두 화면은 가운데 제한된 폭의 폼 하나를 두고 모바일 폭에 맞춘다. 기존에 확정한 Pretendard·연한 회색 배경·초록색 버튼 스타일을 적용한다.
- 기존 임시 로그인 폼을 사용하던 강연방 인증 진입은 `/login`으로 교체한다.

## 구현 및 실행

- 프론트·백엔드 실행 후 `/login` 또는 `/signup` 접속. 실제 `/api/v1/auth` API와 세션 쿠키·CSRF 클라이언트를 사용한다.
- 회원가입 후 이메일과 완료 안내만 React Router의 이동 상태로 전달한다. 비밀번호·확인 입력은 컴포넌트 메모리에만 두며 경로 이동 시 폐기한다.
- 인증 복귀 경로는 `/host/rooms/new`와 숫자 ID의 `/host/rooms/{roomId}`만 허용한다. 외부 주소 등은 기본 생성 화면으로 대체한다.
- 강연방 생성·상세 화면에서 이름·로그아웃을 제공한다. 생성 요청 중에는 로그아웃을 비활성화하여 생성 응답과 초안 삭제가 충돌하지 않도록 한다.
- 로그아웃 중에는 강연방 화면을 잠시 닫아 주기 조회와의 경쟁을 막는다. 서버가 이미 미인증(401)을 반환하면 로그아웃 완료로 처리한다. 연결 오류일 때는 초안을 유지하고 다시 시도할 수 있다.
- `/`은 서버 로그인 상태를 확인하여 미인증(401)이면 `/login`, 인증된 경우 `/host/rooms/new`로 이동한다. 상태 확인 실패는 로그아웃으로 간주하지 않고 현재 화면에서 안내·재시도한다.
- STT 확인용 화면은 `/dev/stt`로 이동했다. 녹음·전송·복구 기능은 유지한다. 알 수 없는 경로는 `/`로 이동한다. `/preview/reports`는 유지하며 공통 TypeScript 전환은 포함하지 않는다.

## 검증

- 단위 테스트 23개 통과(인증 입력 검증 3개 + 기존 STT 20개).
- 브라우저 테스트 총 39개 통과(기존 화면 27개·인증 8개·첫 진입 경로 4개). 가입 성공·이메일 전달·비밀번호 비저장·복귀 주소·입력 오류·중복 이메일·응답 유실·로그아웃 실패와 초안 유지 및 첫 진입 인증 분기를 검증한다. STT 회귀 테스트는 `/dev/stt`에서 실행한다.
- 프론트 운영 빌드 및 PC·모바일 레이아웃 확인. 브라우저 자동 테스트는 모의 API를 사용하며 실제 계정을 생성하지 않는다.
- 인증 화면 구현 후 `gradlew.bat build`로 백엔드 전체 테스트 205개 통과를 재확인했다(실패·오류·건너뜀 0). 이번 인증 화면 작업에서는 백엔드 기능 코드를 변경하지 않았다.
