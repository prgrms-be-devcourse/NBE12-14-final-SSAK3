# 연습 모드 설계

설계 인터뷰에서 합의한 범위의 백엔드를 구현했다. 규칙의 기준은 [게임 규칙](game-rules.md), 요청·응답 계약은 [API 명세](api-spec.md), DB 구조는 [기준 스키마](db/schema.sql)다.

## 확정한 범위

- 먼저 백엔드를 완료한다.
- 전체 학습 대상 문제를 최대 10개씩 나눠 제공하며 시간제한이 없다. 매번 10개를 새로 추출하는 방식이 아니다.
- 마지막 묶음은 남은 문제 수만큼 제공한다. 전체 14문제라면 10문제, 4문제 순서로 푼다. 부족한 수를 이전 문제로 채우거나 10개 미만이라는 이유로 시작을 거절하지 않는다.
- 전체 문제를 풀면 학습 완료를 표시한다. 사용자가 명시적으로 처음부터 다시 풀기를 시작할 수 있고, 기존 풀이 이력은 유지한다.
- 진행 중인 연습은 자동 만료 없이 이어 풀 수 있다. 명시적으로 중도 종료하면 제출한 풀이를 보관하며, 전체 제출로 완료한 연습과 구분한다. 미제출 문제는 오답으로 세지 않는다.
- 풀 당시 문제·보기·정답·해설을 보존한다.
- 분야 선택은 출제 대상 필터이며 학습 진도는 분야 간 공유한다. 특정 분야에서 제출한 문제는 전체 분야에서도 푼 문제로 인정한다.
- 정답 여부와 무관하게 답을 제출한 문제를 푼 문제로 계산한다. 중도 종료한 묶음의 미제출 문제는 다음 연습의 출제 대상에 남는다.
- 새로 추가된 출제 가능 문제는 다음 묶음부터 학습 대상에 포함한다. 진행 중인 묶음에는 문제를 추가하지 않는다. 전체 학습 완료 후 추가된 문제도 이어서 풀 수 있다.
- 진행 중인 연습은 회원당 하나만 허용한다. 여러 탭은 같은 연습과 서버의 제출 진도를 공유한다. 다른 연습을 시작하려면 기존 연습을 완료하거나 중도 종료한다.
- 전체 문제 또는 특정 카테고리를 선택할 수 있다. 선택 범위 내 미풀이 문제를 무작위로 최대 10개 배정하고 묶음의 순서는 유지한다.
- 처음부터 다시 풀기는 전체 분야의 진도를 초기화하되 과거 풀이 이력은 보존한다. 진행 중인 연습은 먼저 완료하거나 종료해야 한다.
- 관리자가 숨긴 문제는 진행 중 묶음에서 미제출 상태라면 건너뛰고 해당 묶음의 실제 문제 수를 줄인다. 오답으로 세지 않는다. 이미 제출한 이력은 보존하고 현재 숨김 상태를 표시한다.
- `time_limit_sec`을 기준 스키마와 연습 시작 응답에서 제거한다.
- `started_at`, `ended_at`은 이력 조회와 완료 구분을 위해 유지한다.
- 문제별 풀이 이력을 영구 저장한다. 이유는 [ADR](adr/0002-persistent-practice-history.md)을 따른다.
- 풀이 이력은 자동 보관하고 복습 목록에는 사용자가 선택해서 저장한다. 복습 API는 `matchId` 또는 `practiceSessionId` 중 하나로 출처를 받는다.
- 기준 스키마와 기존 DB에 적용할 변경 SQL을 함께 준비한다. 기존 DB에서는 서버 재실행만으로 컬럼 삭제가 반영되지 않는다.
- 연습 이력은 날짜순으로 조회하며 완료와 중도 종료를 모두 포함한다. 상세는 전체 문제를 기본으로 보여주고, 틀린 문제만 보기 필터를 제공한다. 미제출 문제는 구분해 문제와 보기만 표시하고 정답·해설은 숨긴다. 제출한 문제는 정답 여부와 관계없이 정답·해설을 공개한다.
- 연습 이력에는 풀 당시 내용을, 별도 복습 목록에는 수정된 최신 내용을 제공한다. 복습 목록의 숨김 문제는 사용 불가 상태를 표시하고 내용을 가린다.
- 이력 목록·상세·오답 필터를 지원하는 백엔드 API를 이번 범위에 포함한다.

## 구현과 검증

- `practice_progress.learning_cycle`로 진도를 구분한다. 다시 풀기는 회차를 증가시키며 과거 세션·답안과 복습 목록은 유지한다.
- 모든 연습 변경은 회원 행을 먼저 잠가 직렬 처리한다. 같은 범위로 중복 시작하면 기존 세션을 반환하고, 다른 범위면 진행 중 오류를 반환한다. 여러 탭은 REST 재조회로 진도를 동기화한다.
- 출제 시 문제와 보기를 복사한다. 원본 문제의 현재 상태는 숨김 처리와 진도 집계에만 사용하며, 답안은 출제 당시 보기로 채점한다.
- 마지막 제출 또는 숨김 건너뛰기로 남은 문제가 없어지면 완료한다. 중도 종료는 별도 상태로 남긴다.
- DB 변경 파일과 적용 절차는 [마이그레이션 안내](db/migrations/README.md)에 있다. 실제 개발·배포 DB에는 별도 적용이 필요하다.
- 실제 MySQL 통합 테스트에서 출제 소진, 진도 공유, 신규 문제, 중도 종료, 동시 요청, 과거 사본, 숨김, 권한 검증을 확인한다. `backend`에서 `./gradlew test --tests 'com.csmatch.practice.PracticeIntegrationTest'`로 실행한다.
- 백엔드 전체 `./gradlew build` 통과. 새 스키마와 변경 SQL로 업그레이드한 스키마 모두 배포 프로파일의 Hibernate `validate` 및 애플리케이션 시작을 확인했다.

프론트 화면, 연습 문제 신고, 기존 명세의 미정 기능인 복습 삭제는 이번 구현 범위에 포함하지 않는다.
