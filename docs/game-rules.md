# 게임 규칙 (단일 출처)

기획서 기준. 코드·테스트·문서는 이 문서와 어긋나면 안 된다. 규칙을 바꾸면 이 문서를 먼저 고친다.
**(미확정)** 표시는 아직 팀 합의가 없는 항목이므로 임의로 정하지 말고 확인한다. (현재 미확정 항목 없음)
체스 시계 방식은 폐기했다. 선착순 스피드 퀴즈(문제마다 먼저 맞힌 사람이 득점)만 구현한다. 문제는 CS 객관식만 출제한다.

## 대결 구조

- 1:1 실시간 CS 객관식 퀴즈. 한 판은 **10라운드**, 라운드당 제한 시간 **20초** (서버 기준 타이머).
- 두 사용자에게 같은 문제·같은 보기를 동시에 보여준다. 한 경기 안에서 문제는 중복되지 않는다.
- 라운드가 끝나면 정답과 해설을 보여주고 곧바로 다음 문제로 넘어간다.
- 경기 종류: 레이팅 매치(레이팅 반영), 비레이팅 매치. 연습 모드(혼자 풀기)는 선택 기능.

## 득점·감점

| 난이도 | 정답 득점 | 오답 감점 |
| --- | --- | --- |
| 쉬움 | +20 | -10 |
| 보통 | +30 | -15 |
| 어려움 | +40 | -20 |

- 먼저 처리된 **정답 1건만** 득점하고 라운드가 끝난다. 서버가 부여한 처리 순번(`received_sequence`)으로 판정한다.
- 오답이면 감점되고, **3초 후** 같은 라운드에서 다시 제출할 수 있다.
- 같은 요청 ID(`request_id`)는 한 번만 반영한다(중복 제출 차단).
- 점수 값(`correct_score`, `wrong_score_delta`)은 라운드 생성 시 `match_rounds`에 고정 저장한다.
- 아무도 맞히지 못하고 20초가 지나면 득점 없이 라운드를 종료한다.
- 10라운드 후 점수가 높은 사용자가 승리한다. 점수가 같으면 **무승부**이고, Elo 는 무승부 값(0.5)으로 계산한다.

## 매칭

- 레이팅이 비슷한 상대를 자동으로 찾는다. 처음 범위에서 **10초마다 ±100점** 씩 넓어진다.
- 대기 중 취소할 수 있다. 중복 대기, 취소와 성사의 경합을 막아야 한다.
- 매칭 대기열·진행 중 경기 상태는 Redis 에 둔다. 친구 초대·방 만들기는 없다.
- 초기 탐색 범위는 **±100**, 10초마다 ±100 씩 넓어지고 **±500 에서 멈춘다**. 최대 대기 시간은 두지 않는다(사용자가 취소할 때까지 대기).

## 레이팅

- Elo 방식. 승·패·무승부 모두 경기당 **한 번만** 정산해 `users.rating` 갱신 + `rating_history` 기록.
- 초기 레이팅 **1000**, K 값 **32**. 비슷한 상대와 붙어 이기면 약 +16 (예: 1000 → 1016).
- 티어는 `rating_tiers` 구간으로 계산한다.

| 티어 | 레이팅 |
| --- | --- |
| 브론즈 | ~1200 |
| 실버 | 1201~1400 |
| 골드 | 1401~1600 |
| 플래티넘 | 1601~1800 |
| 다이아 | 1801~2000 |
| 마스터 | 2001~ |

- 문제 오류 신고가 확인되면 해당 경기의 레이팅 변동만 `rating_history` 로 되돌린다(롤백 이력은 `reversed_history_id` 로 원본 참조).

## 연결 끊김

- 한쪽이 끊겨도 라운드는 계속 진행되고, 끊긴 동안은 점수를 얻지 못한다.
- 재접속하면 진행 중인 경기 상태(현재 라운드, 점수)를 복원한다.
- 끝내 돌아오지 못하면 점수 차로 패배하고, 레이팅 매치라면 레이팅에 반영한다.
- 두 사람이 모두 끊기면 경기는 **무효**이고 레이팅은 그대로다.
- 서버 재시작 시 진행 중이던(PLAYING) 경기는 **무효** 처리하고 레이팅은 그대로 둔다.

## 복습

- 경기 결과 화면에서 틀린 문제의 정답·해설을 보고 "복습에 저장"하면 프로필의 복습 목록(`saved_questions`)에 담는다.
- 연습에서 제출한 문제도 정답 여부와 무관하게 복습 목록에 저장할 수 있다. 연습 이력은 당시 내용을, 복습 목록은 최신 내용을 보여준다. 숨긴 문제는 복습 목록에 사용 불가로 남기고 내용·보기·정답·해설은 가린다.

## 연습

- 전체 분야 또는 선택한 분야의 `ACTIVE` 문제를 학습 대상으로 제공한다. 현재 학습 회차의 미풀이 문제를 무작위로 최대 10개씩 묶으며, 마지막 묶음은 남은 수만큼 제공한다. 시간제한과 레이팅 변동은 없다.
- 분야별 진도는 공유한다. 답을 제출하면 정답 여부와 무관하게 푼 문제로 계산하며, 같은 회차에서는 재출제하지 않는다. 새로 활성화된 문제는 다음 묶음부터 포함한다. 대상이 0개면 시작할 수 없다.
- 회원당 진행 중인 연습은 하나다. 여러 탭에서 같은 연습과 진도를 공유하며, 묶음 순서는 유지한다. 제출 전 문제 조회를 반복해도 같은 문제를 제공한다.
- 답안은 현재 문제에 한 번만 제출할 수 있다. 제출 즉시 정답·해설을 공개하며, 마지막 제출 시 연습을 완료한다.
- 나갔다 돌아와도 만료 없이 이어 푼다. 명시적으로 중도 종료할 수 있으며, 미제출 문제는 오답으로 세지 않고 다음 묶음의 대상으로 남긴다.
- 전체 학습 완료를 표시한다. 진행 중인 연습을 완료하거나 종료한 뒤 명시적으로 다시 풀기를 시작하면 모든 분야의 진도가 초기화되며 과거 이력은 보존한다. 완료 후 새 문제가 추가되면 그 문제를 이어서 풀 수 있다.
- 출제 당시 문제·보기·정답·해설과 제출 답안을 영구 보존한다. 이력은 전체 문제를 기본으로 표시하고 오답만 보기 필터를 제공한다. 미제출 문제는 문제·보기만 제공하며 정답·해설은 숨긴다.
- 진행 중 묶음의 미제출 문제가 숨겨지면 건너뛰고 묶음의 실제 문제 수를 줄인다. 남은 문제가 없으면 완료한다. 제출한 이력은 숨김 표시와 함께 보존한다.

## 문제

- 개념(`concepts`)을 근거로 LLM 이 문제를 미리 생성(배치)하고, 별도 호출로 정답을 검증한 뒤 `DRAFT` 로 저장한다. 대결 중에는 LLM 을 호출하지 않는다.
- 관리자가 검수해 `ACTIVE` 로 바꾸면 출제 풀에 들어간다. 신고가 확인되면 `HIDDEN`.
- 출제 시 난이도·분야·최근 푼 문제를 고려해 `ACTIVE` 문제 중에서 뽑는다.

### 문제 생성 규칙

- 문제는 개념 1개를 근거로 만들고 `questions.concept_id` 로 연결한다. 정답의 근거는 그 개념의 `description` 안에 있어야 하며, 설명에 없는 외부 지식을 정답 근거로 쓰지 않는다.
- 오답 후보 풀은 쓰지 않는다. LLM 이 문제마다 보기 4개(정답 1개)와 해설을 한 번에 만든다.
- 보기 4개는 길이와 어투를 비슷하게 하고 정답만 유독 길거나 구체적이지 않게 한다. "모두 정답", "해당 없음", 다른 보기를 가리키는 보기는 쓰지 않는다.
- 생성한 문제는 `source=AI`, 상태 `DRAFT` 로 저장한다.

### 난이도 기준

난이도는 점수(득점·감점 표)와 달리 "무엇이 쉬운 문제인가"의 기준이다. 문제 생성 프롬프트, 검증, 관리자 검수에서 같은 기준을 쓴다. 목표 정답률은 검수 때 난이도가 맞는지 판단하는 참고값이며 서버가 계산하지 않는다.

| 난이도 | 요구하는 사고 | 문제의 모양 | 오답의 성격 | 목표 정답률 |
| --- | --- | --- | --- | --- |
| 쉬움 (`EASY`) | **기억**: 정의·용어·기본 수치 | 한 개념에 대한 직접 질문 | 다른 개념의 설명이라 명백히 구분된다 | 80% 이상 |
| 보통 (`MEDIUM`) | **이해와 구분**: 동작 원리(왜/어떻게), 비슷한 두 개념의 차이 | 한 개념의 세부 조건, 또는 인접한 두 개념의 비교 | 정답과 같은 영역에서 나온 그럴듯한 오답. 개념을 정확히 알아야 걸러진다 | 50~65% |
| 어려움 (`HARD`) | **추론과 적용**: 시나리오를 읽고 결과를 도출 | 구체적 상황(쿼리, 호출 순서, 수치 계산, 설정)을 주고 한 단계 이상 추론해야 한다. 예외·엣지케이스·트레이드오프 | 부분적으로 맞는 오답. 조건 하나를 놓치면 고르게 된다 | 25~40% |

판별 질문:

1. 개념 이름과 정의만 알면 바로 풀리는가? → 쉬움
2. 정의를 알아도 비슷한 개념과 구분하거나 원리를 이해해야 하는가? → 보통
3. 정의를 알아도 상황을 읽고 조건을 따져 한 단계 이상 추론해야 하는가? → 어려움

- 어려움도 정답의 근거는 개념 설명 안에 있어야 한다. 용어만 어렵게 쓴 문제는 어려움이 아니다. 정의를 외우면 풀리는 문제는 보통으로 내린다.

## 범위 밖 (만들지 않는다)

소셜 로그인, 전체 랭킹, 상세 전적·통계, 추가 대결 방식(스코어 어택 등)·문제 유형(버그 찾기, 코딩), 사용자 문제 등록, 친구 초대·방 만들기, 의심 경기 검토, 서버 다중화·모바일 앱·결제·다국어.
