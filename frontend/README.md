# STT 녹음 컨트롤 (SCRUM-170)

`src/stt/SttPanel.jsx`는 강연자 화면에 붙이는 컴포넌트다. 현재 루트 화면은 실제 인증·STT API를 사용하는 연결 확인용 화면(`SttDemo`)이다. 강연방 생성·시작 UI는 포함하지 않는다.

```jsx
<SttPanel userId={me.userId} roomId={roomId} authRevision={loginRevision} />
```

- `me`는 `/api/v1/auth/me` 결과를 사용한다. 프론트의 ID로 서버 권한 검사를 대신하지 않는다.
- `authRevision`은 같은 계정으로 재로그인할 때 증가시키는 값이다. 남은 기록 전송을 재시도하고 마이크는 자동으로 켜지 않는다.
- 브라우저에서 현재 인식한 최근 확정 전사 30건을 표시한다. 과거 서버 기록을 모두 보여주는 조회 화면은 별도 기능이다.
- `recorder.js`: 시작·재개·종료, 전송 순서·재시도, 누락 구간, 계정 확인.
- `speech.js`: Web Speech API 어댑터, 임시/확정 결과 추적, 추정 시각 산정.
- `storage.js`: IndexedDB의 계정·강연방별 원자적 스냅샷과 Web Locks 탭 제어.
- `api.js`: 동일 출처 세션 쿠키 요청, 10초 요청 타임아웃. 프록시는 기존 Vite/Nginx 설정을 사용한다.

## 실행

```sh
npm ci
npm run dev
```

1. 백엔드와 MySQL·Redis를 먼저 실행한다.
2. Chrome에서 `http://localhost:5173`으로 접속하고 기존 강연자 계정으로 로그인한다.
3. 본인이 소유한 `LIVE` 강연방 ID를 입력해 연결한다. 강연방 준비는 기존 API/담당 기능에서 수행한다.
4. 녹음 시작을 누르고 마이크 권한을 허용한다. 임시 결과, 확정 전사, 저장 상태를 확인한다.
5. 종료를 누르면 최종 전사와 누락 요청 저장 후 서버 세션을 종료한다.

배포는 HTTPS가 필요하다. 로컬 HTTP에서 로그인 쿠키가 전달되지 않으면 백엔드의 로컬 실행 설정에서 `SESSION_COOKIE_SECURE=false`를 지정한다. 배포용 Secure 쿠키 설정은 유지한다. 브라우저 저장소·Web Locks·Web Speech API를 사용할 수 없는 환경에서는 녹음 시작을 차단한다.

## 검증

```sh
npm test
npx playwright install chromium
npm run test:e2e
npm run build
```

Node 테스트는 재전송 멱등성, 마지막 발언 저장 순서, 누락 구간 의존성, 인증 만료, 저장 실패, 보관 기록 등을 검증한다. Playwright 테스트는 실제 IndexedDB와 Web Locks를 사용하되, **음성 인식 엔진과 HTTP 응답은 대역**이다. 실제 음성 인식 품질이나 실제 서버와의 브라우저 통신을 검증한 것으로 해석하지 않는다.

실제 Chrome에서는 다음 항목을 모의 강연으로 확인한다.

- 한국어 문장·영어 기술 용어 인식 품질 및 장시간 인식의 중단/재시작.
- 실제 발언과 추정 시각의 오차. 결과 관측 시각이므로 발언보다 늦거나 구간이 짧을 수 있다.
- 마이크 권한 거부, 네트워크 단절, 로그인 만료 후 복구.
- 새로고침 후 수동 재개, 두 탭 녹음 차단, 종료 후 MySQL 저장 결과.

## 보관 및 복구 한계

- 확정 전사·누락 요청은 서버 성공 응답 후 전송 대기에서 제거한다. 서버 저장을 포기하거나 거절당한 기록은 같은 계정에서 JSON으로 내려받거나 삭제할 수 있다.
- 계정·강연방별로 기록을 구분한다. 비밀번호·세션 쿠키·음성 파일은 IndexedDB에 저장하지 않는다.
- 시크릿 창·다른 브라우저·다른 기기는 같은 탭 잠금을 공유하지 않는다. 서버의 강연방당 세션 제한은 별도로 적용된다.
- 브라우저 데이터 삭제/저장소 축출, 저장소 장애 중 메모리에만 남은 기록, 강제 종료 직전의 아직 완료되지 않은 저장은 복구를 보장할 수 없다.
- 갑작스러운 종료의 정확한 중단 시각을 모르면 과거 구간을 추측하지 않는다. 복구 시 확인한 중단 시점부터 기록한다.
- 초기 구현은 추정 시각이며 DB 변경은 없다. 보고서 기능에서도 API 명세의 추정 시각 안내를 적용해야 한다.
